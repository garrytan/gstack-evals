# Adapters, isolation and egress

Each lane has one owner of isolation and egress (plan v3.2, "Lane B: trial runner and contract"). This file records which, and how each host adapter runs.

## Lane A: src/trial and the host adapters

Owner: U9 (src/trial), with U10 (the Claude Code and Codex adapters).

**Images.** `docker/trial.Dockerfile` builds the trial image from an empty build context, so no repository file and no eval fixture can enter it. Every FROM is pinned by digest, and glibc is present because the metering proxy loads `libc.so.6` for its journal lock. Installs happen at build time with egress, never inside a trial. `gstack-evals doctor` builds the image (E_IMAGE_BUILD on failure), tags it by its recipe hash, labels it with the hash, and pins its digest under `<state>/images/`. `GSTACK_EVALS_DOCKER_BIN` names another docker client. The recipe hash (`src/rig/recipe.ts`) covers the Dockerfile, bun.lock, the FROM pins, the host CLI versions in `docker/host-cli.json` and the adapter tree (`git rev-parse HEAD:src/adapters`). The session cache key and the verdict's rig block take the same hash.

**Pins.** Before a run starts, `checkImagePin` refuses with E_IMAGE_STALE when no image is pinned for this checkout's recipe, when the tag now names a rebuilt image, when the label names another recipe, or when the digest differs from the one the run (on resume) or its preregistration recorded. A run never starts on a rebuilt image by mistake (GST-59).

**Arm images.** An arm image is the trial image plus the arm's installed tree, copied in as content-addressed layers and tagged by a hash of the base digest, the staged tree and the destinations. The build drops `.git`, any path with a segment spelled like `skill-evals` in any case, with or without the dash or the final s (gstack keeps its eval tasks under `test/fixtures/skill-evals/`), and any file with the same bytes as a file in the tasks directory. Modes come from policy, never from the layer's tree: directories 0755, files 0755 or 0644, and 1777 only for `~/.claude`, `~/.codex`, `~/.local` and `~/.local/share`. The built image is then scanned whole, and an arm image that still holds a fixture refuses with E_IMAGE_BUILD.

**Arm installs (GST-272).** `src/arms/install.ts` turns each arm into layers laid out from the agent's HOME.

- *Source.* A stack tree comes from a local git repository that already holds the commit: the checkout a base was inferred from, a gstack checkout on this machine, or a repository under `<state>/sources/`. The rig never fetches (E_STACK_SOURCE): every git call on the source runs with `--no-replace-objects` and `GIT_NO_LAZY_FETCH=1`, so a replace ref cannot swap in another tree and a partial clone cannot fetch a missing blob. `git archive` extracts the tree, and its bytes, hashed again in an empty repository with every git attribute off, must give the commit's tree id, or the folder's for a `<repo>@<sha>:<path>` ref (E_STACK_DIGEST).
- *Install.* The tree's own installer runs (gstack's `./setup --host <host> --no-browser -q`, or the one src/arms/stacks.ts lists for pstack and tstack) with the checkout at `~/.local/share/<name>`, named for the repository or the listed stack, in a builder container from the pinned trial image as this machine's uid. It has egress for `bun install --frozen-lockfile`, whose packages `bun.lock` pins by integrity hash, and a fresh Bun cache of its own, removed when the install ends, so one arm's installer cannot change the packages another install reads. This is build time; a trial never fetches. The kept output is the checkout, the host's skills directory and Claude Code's `settings.json`. `~/.gstack`, `~/.bun` and the host's own state are dropped, since each trial seeds its own state root, and so are `.git` and eval fixture paths, which are also removed from the tree before its installer runs. Links into HOME become relative. Files become 0644 or 0755 and directories 0755, except `~/.claude`, `~/.codex`, `~/.local` and `~/.local/share`, which become 1777 like HOME so the CLIs can write their own state while the root-owned install stays read-only. Every install and derived layer is cached under `<state>/installs/` and checked against its recorded digest when reused (E_STACK_DIGEST). A run deletes the entries it built when it ends (docs/rig.md, Disk space).
- *Arms.* A base arm is two layers: the base minus the target skill, installed, which is the none arm and is built once as its own image; then every file that installing the arm's skill folder in place of the base's adds or changes. Each base arm runs the installer on its own tree, so the host's render of the skill (Codex's `gstack-<skill>`) is the installer's own. A layer cannot delete, so an overlay that would remove a base file refuses with E_IMAGE_BUILD. A stack arm is its tree, or one folder of it, installed whole. A listed stack's rig-authored files (tstack's `~/.claude/agents/sol.md`) are a second layer, with each file's sha256 in the provenance, and a stack that is a Claude Code plugin (pstack) records its plugin root, which the Claude Code adapter loads for each session as a plugin directory. docs/stacks.md lists the stacks. A placebo arm is Lane B's placebo generator (`quick/laneb/arms/placebo/placebo.ts`, its default seed) applied to the named arm's installed skills directory: every skill folder keeps its name and one SKILL.md with its front matter (less hooks) and the router's routing text, and every body becomes prose of the same o200k token count. For a plugin arm it does the same under the plugin's skills/ and keeps only the plugin's manifest. A loose folder is one layer at `~/.claude/skills/<name>` or `~/.codex/skills/<name>`.
- *The skill.* The target skill is the folder under the host's skills directory, then under each plugin root's skills/, whose SKILL.md names it in its front matter, links followed inside the tree, so Codex's `gstack-learn` counts as `learn`. Its roots, for `opened`, are every path that reaches it, such as `~/.claude/skills/learn`, `~/.claude/skills/gstack/learn` and `~/.local/share/gstack/learn`.
- *Images.* Builds are reproducible: no provenance attestation, `SOURCE_DATE_EPOCH=0` and layer timestamps rewritten to it, so the same trial image and layers give the same image digest. `<out>/arms.json` records each arm's provenance (base or stack repo, sha, subtree path, source, git tree and tree sha256, and rig-authored files' sha256; placebo generator hash and seed), its layer trees, its plugin roots and its image digests, and each cell's tree, layer and image digest when the caller passes cells (src/arms/cells.ts).

**A trial.** Setup, the agent and the check each run in their own container as this machine's uid, with every capability dropped and no new privileges. The work dir is mounted at `/work/<task id>`, so the agent sees the task id as its project name and never the evaluator's layout.

1. Setup runs with the work dir and a read-only copy of the tasks directory at `/fixtures` (`SKILL_EVAL_FIXTURES`), and no network.
2. The state root is seeded: `.gstack-home` with gstack's onboarding markers and config (telemetry, update checks, artifact sync and codex reviews off, the CLAUDE.md routing offer declined, proactive at the run's value), after setup so a setup that commits its tree never commits them. `GSTACK_STATE_ROOT` and `GSTACK_HOME` both name it.
3. The work dir is snapshotted as the evaluator-owned baseline, with its .git.
4. The agent runs in the arm image with the work dir only. The tasks directory, the sidecar, personas, mutants and hidden tasks never enter its container or its env.
5. The agent's filesystem delta is imported against the baseline into a fresh copy: new, changed and deleted files anywhere in the work tree, untracked and git-excluded files included. Every .git entry stays the baseline's, so a commit cannot move the grader's HEAD, and so do .gitignore, .gitattributes and .gitmodules, so an agent cannot change what git ignores or how it diffs; one whose directory the agent deleted or replaced with a file goes with that directory and is listed under `deleted`. Fifos, sockets and devices are dropped. A symlink that points outside the work tree becomes an empty directory holding `.gstack-evals-dropped-symlink`, so `test -e`, `test -d`, `find` and git's untracked list still see the path; when the check passes, it runs again on a copy without those placeholders, and the trial passes only when that run passes too (a fail or an error there is a fail, never a missing cell), so a placeholder satisfies neither a check that forbids the path nor one that needs it. Each of these is named in `delta.json`'s `dropped` list and on the trial record, and the verdict warns DELTA_DROPPED for that task. A sidecar `paths` list narrows the import. The check can read `delta.json` through `SKILL_EVAL_DELTA`. Preflight's vacuity controls do not supply `SKILL_EVAL_DELTA` yet, so a check cannot rely on it until they do.
6. The check runs on that copy with a read-only copy of the tasks directory, a read-only root filesystem and no network. Its exit is judged by `judgeCheck`; a check that cannot judge leaves a missing cell (E_VERIFIER).

Each child's env comes from its role's allowlist (`src/trial/env.ts`); the provider key lives only in the proxy. Evaluator records (`trial.json`, `delta.json`) sit beside the work dir, never inside it. Preflight's vacuity controls and `--lock` run in containers on the pinned trial image too. `--isolation process` runs setup and check as this user, each with a fresh HOME, and the agent under bubblewrap with the system directories read-only, the trial's own HOME (kept across its steps) and the work dir; without `bwrap` it refuses (E_ISOLATION_UNSAFE). A real-host run is counted (it leases from a ledger line item), so it refuses `--isolation process` with E_ISOLATION_COUNTED; the fake host, `--dry-run` and the tests keep it.

**Claude Code adapter.** `src/adapters/claude-code/driver.ts` drives Claude Code through the Agent SDK (`@anthropic-ai/claude-agent-sdk`, pinned in package.json) over bidirectional stream-json. The SDK, its `canUseTool` callback and the user simulator run on the evaluator side; the CLI runs in the agent session through `AgentSession.spawn` (`docker exec -i` into the arm container, or bubblewrap), so only stdio crosses the boundary. The trial image installs the CLI the SDK bundles, at the version `docker/host-cli.json` pins, from its npm tarball checked by sha256. The agent env names the session's proxy slot for the cell's provider (`ANTHROPIC_BASE_URL`), carries the slot's bearer as `ANTHROPIC_AUTH_TOKEN`, pins every model variable to the cell's model, holds each request to the proxy's output cap (`CLAUDE_CODE_MAX_OUTPUT_TOKENS`), leaves retries to the proxy, which journals every paid attempt (`CLAUDE_CODE_MAX_RETRIES=0`), and turns off bundled skills, updates, telemetry and nonessential traffic. An arm's plugin roots load for the session as plugin directories through the SDK's `plugins` option. When the caller passes a cell's Codex voice, the adapter first writes `~/.codex/config.toml` for the slot and sets `OPENAI_API_KEY` to the slot's bearer (docs/stacks.md, Cells; E_CODEX_CONFIG). WebSearch and WebFetch are disallowed. Permission mode is `default`, so every Bash and Write call reaches `canUseTool`, which allows it and records nothing beyond the transcript. The adapter writes `transcript.ndjson` (every SDK message), `init.json` (tools, skills, versions), `calls.json` (calls[], opened, files read), `usersim.ndjson` and `cli-stderr.log` beside the trial, never in the work dir. A proxy refusal reaches the session as an API error carrying its code: CAP_STOP ends the cell as a cap stop, E_KEY_REJECTED as rejected credentials, and the other refusals and provider failures leave a missing cell. A CLI crash is an arm failure; the wall clock is a timeout.

**OpenRouter on Claude Code.** An OpenRouter model such as particle-1 runs on a Claude Code arm through OpenRouter's Anthropic-compatible `/v1/messages` route. The proxy forwards it with `OPENROUTER_API_KEY` as a bearer, replaces the request's provider routing with the price row's, and reads usage in Anthropic's shape (cache reads and writes beside `input_tokens`). The routing the proxy sends on every OpenRouter call (`openRouterRouting` in `src/runner/pricing/prices.ts`) holds `data_collection: "deny"`, so OpenRouter skips any host that may train on or keep prompts; the row's providers as `only` with no fallbacks; the row's quantizations, when it pins any; and the row's input and output prices as `max_price`. particle-1 is pinned to particle-ai. DeepSeek V4.1 Flash is pinned to inference-net at fp8 ($0.08 in, $0.55 out, $0.008 cache read per 1M tokens, read 2026-10-31): DeepSeek's own endpoint may train on prompts, so data_collection deny leaves it no route, and this rung's results come from a third-party fp8 host, not DeepSeek's endpoint. OpenRouter says Claude Code is only guaranteed on Anthropic's own models, so each open rung needs its calibration and a tool-use smoke before a counted run.

**Codex adapter.** `src/adapters/codex/driver.ts` runs `codex exec --json` in the agent session and reads its JSONL events on the evaluator side. It runs non-interactive tasks only: a task declared interactive ends as a missing cell, E_INTERACTIVE_HOST, before anything starts, as preflight already refuses it. The command line defines a model provider for the proxy (the session's slot for the cell's provider, the Responses API, the slot's bearer read from `OPENAI_API_KEY`, retries off so the proxy owns them) and turns off Codex's bundled system skills (`skills.bundled.enabled=false`), web search, the update check and analytics, all under `--strict-config`. Approvals and Codex's own sandbox are bypassed, since the trial container is the sandbox. The prompt goes in on stdin. The adapter writes `transcript.ndjson`, `init.json` (the command line), `calls.json` and `cli-stderr.log` beside the trial. Turns are the agent messages, the last being the final answer; calls are shell commands (ok on exit 0), file changes and MCP calls, so the skill opens on a shell read under one of its roots. A completed turn completes the session; a failed turn naming a proxy refusal maps as on Claude Code, and any other failed turn is a missing cell, UPSTREAM; a CLI that exits without a turn result or is killed is an arm failure. In exec mode Codex answers a `request_user_input` call itself as unavailable and reports nothing, so such a question is not recorded. The trial image installs the Codex binary from the npm tarball `docker/host-cli.json` pins, checked by sha256, and package.json pins the same version for the keyless tests.

**Calibration and the run loop on a real host.** Before any trial, per model, `src/adapters/calibration.ts` runs one session per arm and a shell check. An arm that holds the skill runs on a calibration copy whose SKILL.md ends with a sentinel line only that copy holds; it must quote its own sentinel, quote no other, and show the read (CALIBRATION_SKILL). An arm without it must answer NO-SKILL, quote no sentinel and read no copy (CALIBRATION_NONE_LEAK). The shell check's output is computed by the shell and must come back with a successful call in calls[] (CALIBRATION_SHELL). On Claude Code, when a task has scripted replies, one AskUserQuestion round trip must return the scripted answer (CALIBRATION_USERSIM). The evaluator itself probes a non-model host from an agent container on the trial network, and it must fail (CALIBRATION_EGRESS). When an arm installs a gstack tree, one session runs its `gstack-skill-start` through the host's shell, and the output must carry `PROACTIVE: core` and `ROUTING_DECLINED: true` (the seeded values) and `SESSION_KIND: interactive` (what gstack resolves under both adapters, which set no `GSTACK_SESSION_KIND`), from a call that succeeded (CALIBRATION_CONFIG); with no such arm the check is null. A failed check skips every trial, and the verdict exits 3. Then `src/skill-eval/cli/run-host.ts` runs round 1 and the rerun stage as the fake host does, each session a U9 trial on its own proxy slot, starting a round only when its worst case fits under the cap, and rewriting progress.json after each session. The Docker rig installs every arm (Arm installs, above), builds one arm image per arm and a calibration copy on top of it, keeps the trial image and every layer tree by digest, opens the lease, starts the proxy container on the trial network, binds slots over the management socket, and on close stops the proxy, reconciles its journal and settles the lease.

**Adjudication.** A task with a judge rubric sends each completed run to its own session of the judge model (`--judge-model`, from the other family) (`src/grade/adjudicate.ts`). A judge session is one model request that declares no tools (`src/adapters/judge.ts`): no host CLI runs, so the judge cannot run a command or read a file, and it can only answer from what it is sent. On the OpenAI route the request pins its reasoning effort at `JUDGE_REASONING_EFFORT` (medium); the Anthropic and OpenRouter routes send no thinking or reasoning field. The request leaves from a container with no skill installed and no copy of the agent's work, on its own proxy slot. The judge's prompt holds the task's prompt, the rubric, the text the user saw (the final answer, or every turn of an interactive task) and the evidence (the files the session added, changed or deleted, and the check's result). It never names the arm, the skill, the model or the host: the skill's name and "gstack" are redacted from the answer and the evidence, the session runs in a randomly named directory under `<out>/judge`, and no two runs share a session. The answer and evidence sit between tags carrying a per-session nonce. The judge's final message must be exactly one line, done, not done or unknown; anything else is unknown. A judge session that cannot finish leaves the run unjudged and the verdict stops with JUDGE_UNAVAILABLE; one stopped by the cap stops the run as a cap stop. Safety tasks are never sent, since a judge never overrides one. Each judgment, with its directory, redaction count, termination and cost, goes to `<out>/adjudication.ndjson`, and each judge session is priced into a round's worst case before the round starts.

**User turns.** `src/grade/transcript.ts` parses what the verdict grades: the user-visible turns (the main agent's text blocks and each AskUserQuestion's question with its option labels, never user or persona text, tool input or output, thinking, subagent messages or API errors) and calls[], each tool call with whether its result succeeded. The skill counts as opened only on a successful Skill call naming it, bare or under a plugin namespace such as `pstack:interrogate`, or a Read or shell read under one of its roots.

**User simulator.** `src/usersim/sim.ts` answers each question from the task's sidecar replies by the classifier's category. A question's effects come from its header, text, option labels and option descriptions. A question that names a gated effect (write, create, edit, delete, commit, push, merge, deploy, run, send) gets its category's reply as written only when the reply refuses, and a refusal is either bare ("No, not yet.", "Hold off for now.") or negates each effect word directly and covers every effect the question names ("don't push", not "don't hesitate to push" or "No objection."). Any other reply may authorize the effect, so it goes out only when it names every effect the question names, is not an ordinal, and the classification is unambiguous; otherwise a fixed non-approving answer goes instead and the event log marks the reply misaligned (REPLY_MISALIGNED). A reply that names an effect the question does not name is held back the same way unless it refuses. A question with no reply gets the persona's free-form answer when the run has one, sent only when it refuses if the question or the answer names a gated effect, else a non-approving fallback. An AskUserQuestion in a task with no `user` replies ends the trial as a missing cell, E_USER_TURNS_MISSING, naming the question. Every question, its classification and effects, the reply and its source go to `usersim.ndjson`, which starts with the rules' sha256.

**Persona model.** On a real host, a persona's free-form answers come from the policy's usersim model (`defaults.usersim`; the policy's sha256 is in each session key). Each answer is one request with no tools, at most 1,024 output tokens and, on the OpenAI route, reasoning effort `PERSONA_REASONING_EFFORT` (low), sent from the judge's sandbox through the session's own usersim slot under the run's lease, with the persona, the question and its options in the prompt (`src/usersim/persona.ts`). The session's clock stops while an answer is pending. The usersim meter adds to the run's spend and to `<out>/usersim.ndjson`, and a round's worst case counts one usersim allowance per persona session. A usersim cap stop stops the cell as a cap stop; a proxy refusal or provider failure leaves a missing cell with its code, and a timeout or crash leaves one with E_USERSIM. Codex runs no persona task: it refuses interactive tasks with E_INTERACTIVE_HOST, since exec mode answers `request_user_input` itself.

**Approval path.** The Claude Code adapter registers an SDK-side PreToolUse hook that answers `ask` for every tool call, so each call reaches `canUseTool` even when a fixture's or the agent's `.claude/settings.json` allows it, adds a settings hook that allows it, or sets bypassPermissions (tested on the pinned CLI, 2.1.314). An AskUserQuestion whose result did not come through `canUseTool` voids the trial as a missing cell, E_APPROVAL_BYPASS. That covers an answer from elsewhere and another hook's deny reason, which the CLI hands the model as the result.

**Network.** A run that spends gets its own internal Docker network on a free `10.231.x.0/24` and a separate egress network. The internal network has no route out and uses Docker's isolated gateway mode (Engine 28 or newer), so the host has no address on it for an agent to reach (`src/trial/proxy.ts`). The metering proxy runs in its own container on the trial image, joined to both: its trial listener binds a fixed address on the internal network, and the egress network is its only route out. Agent containers join the internal network alone, so the proxy is the only address they can reach: no outside IP, no DNS, no gateway. The provider keys and the management credential reach the proxy through its own env allowlist and never an agent's. The proxy's config, journal and management socket sit in an evaluator-side directory mounted into the proxy container only; the runner puts it under `<out>/proxy`, so the receipts copy below carries the journal.

**Resume.** A real-host run writes `<out>/run.json` (its lease, proxy container and journal) when it starts, and appends each finished session with its cache key to `<out>/cells.ndjson`. `--resume <out>` refuses a run that ended on a terminal stop (E_NOT_RESUMABLE). If the earlier attempt never closed, it recovers in one order (`recoverRun`): stop the proxy container, run `reconcileJournal` on its journal, then settle the lease. Then it reuses each journaled session whose key still matches, runs the rest under the cap left over, and stops with E_CACHE_STALE before any spend when a key changed. `--repair <name> --resume <out>` reruns those changed cells instead, under a new verdict id. A running proxy holds the journal's flock and reconcile refuses while it does. Settling first would close every hold whose answer was lost as unknown, at its full reservation, where reconcile releases it at $0.

**Receipts.** A run refuses to keep its proxy journal or receipts under the OS temp dir, `/tmp`, `/var/tmp` or `/dev/shm`, or on a tmpfs or ramfs mount (`src/trial/durable.ts`). On a VM the runner deletes afterwards, such as a Ubicloud smoke run, `GSTACK_EVALS_EPHEMERAL=1` says so, and the run then needs `GSTACK_EVALS_RECEIPTS` naming a directory that outlives the VM. Before it exits, the run copies its receipts and journal there, keeping their paths under `<out>`; a file outside `<out>` is refused before anything is copied.

**Cache and progress.** Each session is cached under a sha256 over named parts: the arm tree, the task and its sidecar entry, the fixture tree, the verifier code, the trial image digest, the recipe hash, model, host version, adapter sha256, isolation, `--timeout`, the passthrough env values (hashed, never stored), the judge model and the policy (`src/trial/cache.ts`). A resumed session whose key differs stops before any spend with E_CACHE_STALE, naming the parts that changed. `<out>/progress.json` is rewritten atomically after every session with counts, the cells still running and an ETA.

**Retention.** A run keeps every image and arm tree it uses under `<state>/retained/`: `images/<image id>.tar` from `docker save` for the trial image, `trees/<tree sha256>.tar` as byte-stable tars for every arm layer, and `MANIFEST.jsonl` listing each with its sha256 and size. An arm image is not saved whole, since each would repeat the trial image: it is rebuilt byte for byte from the retained trial image and layer trees, and `<out>/arms.json` names its digest to check against. The retention target: every retained file of a counted run stays fetchable by digest for as long as any report cites the run, so a replicator gets the exact bytes. The run's results pull request names where the files went. Until the program has its own bucket, that is a GitHub release on garrytan/gstack-evals named for the run id, one asset per digest. A retained file a published report cites is never pruned.

**Docker tier.** Tests that need a Docker daemon skip unless `GSTACK_EVALS_DOCKER=1`, so the default CI job stays fast. U20's rig.yml runs them and counts a skipped expected case as a failure.

## Lane B: the runner chosen by the Harbor spike

Owner of isolation and egress: **Harbor**, chosen by the U8 spike ([finding](../wiki/board/2026-10-28-gsta-10-harbor-spike-lane-b-runner.md)). gstack-evals owns the metering proxy, the ledger, preregistration, stats and reports. M2a's Lane B rig is not built yet; this section is the contract it builds to. GSTA-12's exploratory quick look, [quick/laneb/](../quick/laneb/README.md), runs on Harbor ahead of M2a; its README lists what M2a should keep and the quick look's known gaps.

**Runner.** Harbor, pinned by commit (f3a5a923 or later) until a release carries `skip_install` (harbor#3657). The pin goes into the arm manifest and the preregistration. The agent subclasses Harbor's `ClaudeCode` and calls private helpers (`_resolve_auth_env`, `_resolved_model_name`, `_model_alias_env`, `_sanitize_docker_compose_project_name`), so moving the pin means rerunning the spike's six checks. Tasks are Harbor task directories under `tasks/<track>/<task-id>/`.

**Agent.** Our own Harbor agent drives Claude Code through the Agent SDK, the same adapter shape as Lane A (stream-json with `canUseTool`). The SDK runs in the Harbor process on the evaluator side. Its CLI subprocess runs inside the trial container through `docker exec -i`, so stream-json and the question channel cross the boundary over stdio only. The env passed into the container is an explicit allowlist: `docker exec` forwards only the names the agent set, never the rest of the Harbor process's environment. The values of those names can still come from that environment: the API key does, through Harbor's auth helpers, so the Harbor process's environment holds only the metering proxy's key, and the provider key lives only in the proxy process. Harbor's built-in `claude-code` agent (`claude --print`) and its ACP bridge are not used: the first cannot answer AskUserQuestion, and the second runs the simulated user inside the task environment.

**User simulator.** Evaluator side only. The persona never enters the container; only the answer to each question does, as the tool result. Every question, answer and reply source goes to `usersim-events.jsonl` in an evaluator-only directory beside the trial's `agent/` directory, never inside it: Harbor bind-mounts `agent/` read-write into the container at `/logs/agent`, so anything written there can be read or rewritten by the agent under test. The same holds for the SDK message log.

**Model endpoint.** The metering proxy, passed as `--base-url`. Harbor sets `ANTHROPIC_BASE_URL`. Its own defaults for the tier aliases and `CLAUDE_CODE_SUBAGENT_MODEL` keep any value already set in the trial env or in the Harbor process's environment, so the agent pins every alias Harbor lists to the cell's model itself, and the trial env stays an explicit list.

**Arms.** Baked into the task image: the host CLI at a pinned version, the arm under the baked `CLAUDE_CONFIG_DIR`, and the gstack configuration. Trials run with `--ak skip_install=true`. Proposed, pending the Captain's decision (see the finding): every arm sets `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1`, since Claude Code otherwise loads 16 bundled skills in every arm, and each trial records the skills list from Claude Code's init message.

**Network.** Per phase, in `task.toml`:

| Phase | Policy | Why |
|---|---|---|
| `[environment]` (setup) | `no-network` | Nothing installs during a trial |
| `[agent]` | `allowlist` with no hosts listed | Harbor allowlists the proxy's host on its own, every port on it, and refuses other TCP; DNS, ICMP and marked packets are the exceptions below |
| `[verifier]` | separate environment | Grading never shares the agent's container |

Harbor's Docker egress sidecar shares its network namespace with the agent container. Its nftables rules redirect TCP through a proxy that matches on SNI, Host or IP and reject other traffic, with three exceptions: DNS to the container's resolver, all ICMP, and any packet carrying the sidecar's own mark (114514). The allowlist is per host: Harbor drops the port from the base URL, so every TCP port on the proxy's host is reachable, and the proxy needs a host or address that serves nothing else to trials. DNS stays open as a slow side channel. ICMP stays open in both directions, to any host, even after the capability drop below, because Docker lets unprivileged users open ICMP echo sockets. Lane B containers hold no answer keys, so both are accepted and stated. The mark is not: a root process with Docker's default capabilities can set it (`SO_MARK` needs only `CAP_NET_RAW` on Linux 5.17 and later) and bypass the allowlist, and `CAP_NET_RAW` also opens `AF_PACKET` sockets that send below the sidecar's rules. So the agent runs as a non-root user in a container that drops `NET_RAW` and `NET_ADMIN`. Preflight checks that the agent's effective capabilities lack both, that a marked socket and an `AF_PACKET` socket both fail, and that no service in the task's or the run's Compose files declares `network_mode` or `networks`, since Harbor leaves such services, `main` included, outside the sidecar. WebSearch and WebFetch are removed under a restricted policy, and the metering proxy refuses requests that declare server-side tools.

**Host.** A Linux Docker host whose kernel has `CONFIG_NF_TABLES_INET` and `CONFIG_NFT_FIB_INET`: stock Ubuntu (Ubicloud, GitHub runners). Capy cloud machines lack both, and Harbor refuses non-public tasks there before starting. Preflight checks the kernel and fails with the fix line.

**Verifier.** Every task sets `[verifier] environment_mode = "separate"` (or `[verifier.environment]`) and declares the artifacts it grades, such as the patch. Harbor copies only `/logs/artifacts/` and declared paths into the verifier, so an undeclared output is not graded. Preflight refuses a task with shared verification.

**Open for M2a.** The non-root, capability-dropped agent above: Harbor's `[agent] user` reaches only Harbor's own exec path, so the SDK transport must pass `docker exec --user <uid>:<gid>` (a bare uid with no passwd entry runs in group 0) and the task's workdir itself. The spike task format has no setting for dropping capabilities, but Harbor's run-level `extra_docker_compose` does: the quick-look runner (`quick/laneb/runner/agent-caps.compose.yaml`) drops `NET_RAW` and `NET_ADMIN` from every trial's main container, which leaves it in the sidecar's network namespace, and its agent's setup refuses a container whose effective or bounding set still holds either. That runner still runs the agent as root, because Terminal-Bench tasks install packages and configure services. The spike agent hardcodes 12 turns and default permissions and ignores Harbor's `max_turns`, `max_budget_usd`, `reasoning_effort` and `permission_mode` options; the production agent forwards or refuses each. Also open: Compose tasks under the allowlist, regrading, and a streaming exec for any non-Docker environment.
