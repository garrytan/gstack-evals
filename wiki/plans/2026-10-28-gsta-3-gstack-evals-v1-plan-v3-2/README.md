### Why it matters

- A gstack skill costs about 13K tokens per invocation (the header of gstack's own arm benchmark), and nothing measures whether it earns them. A skill that does nothing on Opus 5.5 should get shorter or get harder tests. Today we cannot tell which.
- Optimizers delete what is not tested: a diet loop without gate tasks removed an approval gate in the Langfuse case. gstack has started dieting: /learn's template halved in v1.91.287.0, and /plan-design-review, /office-hours (73 to 44 KB) and /design-review (116 to 85 KB) shrank in v1.91.289.0, each on gstack's own skill-diet panel. More diets are coming, and nothing shared yet checks that a diet kept its gates.
- Outside trials found skill packs adding cost without correctness (Superpowers matched no-skills at 3.07x tokens in the preregistered SKT trial), and a third party reported gstack's /review prompt scoring 31.6 F1 against 33.2 for a two-sentence baseline. gstack should know where it stands and say so when it loses.
- If gstack lifts a cheap or open-weight model toward Opus 5.5, the factory gets cheaper and the claim is worth making with receipts. If it does not, that steers R&D just as much.

### Principles

- An R&D instrument. Wins and losses go in the same table, including a gstack skill that loses to none or placebo.
- Grade outcomes from repo state, hidden tests and evaluator-owned event logs, never the agent's account. A run that claims success and fails grading counts toward a false-done rate.
- Paired comparisons: same tasks, harness and model per cell, arms launched together, analysis clustered by task.
- No home team. The placebo arm and a judge from another model family keep our own reading honest.
- Preregister before the first counted cell; amendments are dated and committed before the cells they affect; a changed pin, model or allowlist is a new run.
- Spend only through a ledger under a cap Garry approved. A cap stop is an incomplete run, never retried to change a verdict.
- Models: newest generation per family; no Sonnet; Fable only in smoke tests; never gpt-5.4-mini. These are Garry's crew rules. The tool ships them as its default policy file (`policy/models.json`), on by default and recorded by hash in every verdict, instead of hard-coding them (change d8). A model at ceiling is uninformative, never a tie.
- Existing gbrain verdicts that counted Sonnet cells may be cited as labelled context only. No claim, bar or gate rests on them, and gstack-evals runs no Sonnet.
- Name every denominator. Pass rate, pass^3, recall, cost per success and share of gap closed answer different questions and are never combined.

### Arms and the measured configuration

An arm is a pinned directory plus a host-specific install command; one manifest grammar (`schema/arms.schema.json`) covers Lane A skill versions, Lane B stacks and later stacks.

- Kinds: `bare` (no skills), `placebo`, `stack` (repo at a sha, installed by its own setup), `overlay` (a base stack with one skill folder replaced at its real install path, or removed), and `loadout` (a named set of modules; Amendment A1, unreviewed).
- Isolation: every trial gets a fresh HOME and config directory (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, XDG) holding only its arm; no user memory, no global CLAUDE.md or AGENTS.md, a strict MCP config. Calibration's none check proves nothing leaks in.
- The gstack that is measured, pinned in the arm manifest and the preregistration, and asserted by calibration from the preamble's printed lines:
  - installed by gstack's own host setup into the trial HOME at the preregistered sha (today v1.91.284.0, 10b77de);
  - pre-seeded as an onboarded user, so no first-run prompts and no CLAUDE.md append-and-commit inside the graded repo: the completeness, telemetry, proactive and activation markers set, telemetry off, update check off (egress is denied anyway);
  - proactive mode set to a preregistered value (default `core`), session kind pinned, CI and headless variables scrubbed from the trial env;
  - gstack's skill-routing section committed into the fixture's project CLAUDE.md before the trial, so it is not part of the graded diff or LOC; the placebo arm gets byte-identical routing text; bare and none get none;
  - outside-voice features (`codex exec`) disabled in every arm, recorded.
- Placebo: the gstack arm's folder names, descriptions and routing text, with each SKILL.md body replaced by on-topic, non-procedural text of matched length (within 5% of tokens) from a seeded generator whose hash goes into the preregistration. The placebo is regenerated from each measured gstack tree, and placebo cells are reused only when the generated tree and the execution and grading fingerprints are identical; a token-length or routing edit in gstack invalidates them, with a keyless test. The M2 feasibility step checks on dev that placebo does not differ from bare. gstack minus none decides routes; gstack minus placebo is reported beside it as the mechanism check.
- Trigger wrapper (GSTA-4): every Lane B task prompt goes through one arm-neutral instruction wrapper, identical across none, placebo and gstack, so routing differences come from the arm, not the prompt.
- Model purity per cell: `ANTHROPIC_MODEL`, the default-model variables and `CLAUDE_CODE_SUBAGENT_MODEL` all set to the cell's model; the proxy lease allowlists exactly that model id and counts refusals per trial, which also enforces the no-Sonnet rule mechanically.
- Reasoning effort or thinking mode pinned per rung and recorded (default: the host's default for that model); a change is a new run.
- Skill-opened signal per host, written by the adapter as `calls[]`: Claude Code from the stream-json transcript (a Skill call or a read under the arm's skill tree); Codex from exec events (a shell read of a SKILL.md path); gbrain from an MCP `get_skill` call.

### Lane A: the shared before/after skill eval

**Call.** gstack's contract call works as written, plus a committed lock for paid runs: `gstack-evals skill-eval --arms before=<dir>,after=<dir>,none --tasks <tasks.json> --host claude|codex --model <id> --trials 3 --spend-cap <usd> --out <dir> [--dry-run] [--calibrate] [--tasks-only <id,...>]`. Extensions: `--base <spec>`, `--skill <name>` (the target skill, required with `--base` or a `repo@sha` arm; the host adapter resolves its generated path, such as Codex's `gstack-<skill>`), `--ext <file>`, `--policy <file>`, `--smoke`, `--ledger`, `--isolation docker|process`, `--parallel`, `--timeout`, `--judge-model`, `--margin`, `--resume`, `--repair`, `--mirror`, `--json` and `--arms-file`. One arm-spec grammar on every command: `name=<dir>`, `name=<repo>@<sha>`, `none`, `placebo`. `--runs` is an alias of `--trials`. The repeat arm is called `before2` everywhere and is on by default. When an arm directory is a rendered gstack skill (`<root>/<skill>/SKILL.md` beside `<root>/bin/gstack-skill-start`), skill-eval infers `--base gstack@<git -C <root> rev-parse HEAD> --skill <basename>` and prints it under effective defaults; an explicit `--base` overrides. So the folder /write-skill passes works as written. A loose folder that calls gstack bins but whose root cannot be resolved is refused with E_LOOSE_GSTACK, since it would measure gstack's degraded mode; its fix line carries the resolved values, never a placeholder. A paid call without a committed lock exits 2 (LOCK_MISSING) and prints the exact `--lock` command and the git add and commit for the tasks file's repo; a gstack PR through the Captain adds that step to diet.md step 6. A keyless test runs diet.md's literal call on learn with the fake host.

**Base and overlays.** gstack skills hard-code their install paths (office-hours reads `~/.claude/skills/gstack/office-hours/sections/preamble.md` and runs `gstack-skill-start`), so a loose folder measures gstack's degraded mode. With `--base gstack@<sha>`, before and after are overlays of that base with the target skill at its real path, none is the base minus the target skill, and `bare` (optional) has no gstack. Without `--base`, arms are loose folders, as skill-diet does. Host-specific install manifests let gbrain install through MCP `get_skill`.

**Tasks: gstack's contract, read unchanged.** A tasks file is the contract's bare array, `[{id, prompt, setup?, must?, must_not?, check?, safety?}]`, with the contract's meanings: `setup` and `check` run in the session's work dir, `SKILL_EVAL_FIXTURES` is the tasks file's directory, `must` matches the final answer, `must_not` matches its code blocks, and `safety: true` marks a task whose failure fails the diet on its own. `validate` applies the same rules as gstack's `checkEvalTasks` (kebab-case ids, a non-empty prompt, `must` or `check` present, compiling patterns, unique ids, boolean `safety`, no unknown keys, setup scripts present), and a keyless test runs both on gstack's committed files so the two never drift. What gstack-evals adds lives in an optional sidecar, `tasks.ext.json` beside the tasks file, keyed by task id, so gstack's free test never sees an unknown key: `user` (scripted replies keyed by question category, plus a persona line), `interactive` (true when the task expects questions; implied by `user`), `judge` (a rubric), `timeout_s`, `env` (a passthrough list), `paths` (an optional list that narrows the grader's import), `mutant` (a violating control, `{setup, answer}`: a shell step run after the task's setup that commits the violation, and an optional violating final answer) and `hidden` (the task runs evaluator-side only, so a diet author never sees it). A sidecar entry for an id the tasks file lacks is an error.

**Interactive skills.** office-hours and the plan reviews stop at AskUserQuestion. The Claude Code adapter drives Claude Code through the Agent SDK (bidirectional stream-json with a `canUseTool` callback) and answers from the task's `user` replies. Replies are keyed by question category: the sidecar schema publishes the category list, and a deterministic, recorded rule (keyword and option-label matching, no model) classifies each question. A reply that approves a gated effect is bound to its category and to the effect the question names; ordinals and free-form answers never approve, and an ambiguous match gets a non-approving answer and REPLY_MISALIGNED. Keyless tests insert, remove and reorder questions in front of an approval. Each question's reply source goes into the event log, and the verdict warns REPLY_MISALIGNED when after's question sequence differs from before's. A non-approval question that no reply covers gets the persona's free-form answer from gpt-6-luna at temperature 0 with a fixed seed. Each task's session kind is pinned and written into the verdict. Interactivity is declared per task (`user` or `interactive: true` in the sidecar), never inferred from AskUserQuestion in the skill text, since every gstack skill's preamble mentions it. A missed declaration is caught at run time: an AskUserQuestion call in a task with no replies ends that trial as a missing cell coded E_USER_TURNS_MISSING, naming the task and the question. In v1 the Codex adapter runs only non-interactive tasks: gstack drives Codex only through `codex exec --json`, so a declared interactive task with `--host codex` is refused with E_INTERACTIVE_HOST, which names the interactive task ids and offers both fixes (`--host claude`, or `--tasks-only <the other ids>`) (d5 at gate_rev 2). A keyless test checks that /learn passes preflight on the fake Claude and Codex hosts.

**State root.** gstack skills keep state under `GSTACK_HOME`. src/trial seeds a `.gstack-home` in each work dir, copies the onboarding markers in, and exports both `GSTACK_STATE_ROOT` and `GSTACK_HOME` to it through the env allowlist (gstack reads the state root first), which /learn's fixtures need. A fake-host /learn end-to-end test covers it, and gstack is offered a note to write the convention into SKILL_EVAL_CONTRACT.md.

**Lock and gate coverage.** `--lock` writes `tasks.lock.json`: the tasks file's and sidecar's sha256, the policy version, and the before copy's contract lines (MUST, NEVER, STOP, ask and approval lines, required outputs), each with the task ids that cover it. A line counts as covered only when old-arm runs of a covering task reached it: its section was read and the gated event or required output was observed. A listed but unreached line is uncovered. The committed lock is the run's preregistration: a paid run needs it committed and clean at HEAD, and the verdict records that commit. A run with no lock exits 2 (LOCK_MISSING). A relock reruns the changed tasks in every arm and marks the verdict `post_hoc: true`. An after copy that removes a contract line exits 1 (UNCOVERED_GATE_REMOVAL) unless a task covers that line and still passes in after. Nothing else clears it: every Capy thread acts as the same GitHub user, so no sign-off can be told apart from the diet's author (change d6).

**Free first steps.** Step zero, while the repo is private: clone `https://git.capy.ai/garrytan/gstack-evals.git` at a release tag and `bun link`; `doctor` builds the trial image from the repo's Dockerfile and records its digest. `gstack-evals doctor --host claude|codex` checks Bun, Docker, the trial image digest, the host CLI and version, every key the matrix needs by name (judge included, never the value), and the ledger and its cap, and prints one fix line per gap. `skill-eval --example[=miss|safety|unopened|not-measurable|cap-stop]` runs the fake host on a bundled two-task skill in under 10 seconds with no key and writes a real verdict. `validate --tasks <file>` checks a tasks file against the schema. `skill-eval init --skill <dir>` scaffolds tasks.json with a safety stub per contract line it finds. Every paid command runs the same preflight before any spend: keys, host, Docker, model ids against the price table and the model policy file (by default Sonnet and gpt-5.4-mini refused, Fable allowed only with `--smoke`), lock, ledger, and a vacuity check on the whole task, never on one assertion. The no-op control is an empty answer with the untouched fixture; each `must_not` passes on it by construction, since an empty answer has no code blocks, so no `must_not` is ever judged alone. A non-safety task whose whole pass predicate (every `must`, the `check`, and no `must_not` hit) holds on the no-op control is refused (VACUOUS_CHECK). A safety task may pass the no-op control by design (do no harm while doing the task); it is checked instead against its violating control, the sidecar's `mutant`, on which its predicate must fail, or VACUOUS_CHECK names the assertion that did not bite. A safety task with no `mutant` runs, and its verdict carries the warning NEGATIVE_UNVALIDATED, so /learn's committed safety tasks run as they are. A keyless test runs preflight on gstack's committed learn and write-skill tasks with a lock committed in the test fixture, since gstack commits none; they must pass unchanged.

**Calibration** before every eval, per host and model, in parallel: each skill arm quotes its own sentinel line and shows the read; the none arm answers NO-SKILL and reads no copy; a shell command returns its output and appears in the calls; for gstack bases, the preamble prints the pinned proactive and session-kind values; for tasks with `user` replies, one scripted question and answer round trip completes; an egress probe to a non-model host fails. Each failure exits 3 with a code (CALIBRATION_SKILL, CALIBRATION_NONE_LEAK, CALIBRATION_SHELL, CALIBRATION_CONFIG, CALIBRATION_USERSIM, CALIBRATION_EGRESS) naming the arm, host, model, path read and a fix.

**Execution, isolation and secrets.**
- Docker by default. With no daemon the run exits 2 (E_ISOLATION_UNSAFE) before any spend. `--isolation process` must be explicit, runs the agent under a separate uid or bubblewrap, and is written into the verdict.
- Installs never run inside a trial. Arms and host CLIs are baked into content-addressed image layers built with egress, and trials start from them with installs skipped. The agent container sits on an internal network whose only exit is a dual-homed proxy container.
- Answer key out of reach: the agent container never holds the tasks directory, the sidecar, personas, mutants or hidden tasks. Setup runs in its own container, the work dir is snapshotted as the baseline, and the agent starts with only the work-dir volume. A keyless test plants a canary in the tasks directory and checks that the agent side cannot read it.
- Grader integrity: verification starts from the evaluator-owned baseline, with its .git, and imports the agent's filesystem delta against it: new, changed and deleted files anywhere in the work tree, untracked and git-excluded files included (so `.gstack-home` comes across), excluding only `.git/`, hooks and verifier configuration. A sidecar `paths` list may narrow the import. `check` then runs from a read-only copy of the tasks directory in a fresh container. Keyless tests: an agent changes and commits app code that breaks a safety check, and the check must still fail; a forbidden deletion and a new skill folder grade the same as in the agent's tree; and all 12 committed contract tasks (10 learn, 2 write-skill) replay an oracle and a broken transcript, with every one of /learn's ten checks passing on the oracle and failing on the nop.
- Every agent, setup and check child starts from an env allowlist: PATH, the trial HOME, `GSTACK_STATE_ROOT` and `GSTACK_HOME`, LANG, TERM, the per-session token, the proxy base URL and the task's declared variables. The provider key lives only in the proxy's process.
- The proxy's management routes (bind, unbind, finalize) listen only on an evaluator-side socket with their own credential; a trial token, valid or absent, is refused there, with cross-cell tests.
- The per-session bearer token authenticates one proxy slot and is never persisted or printed: it lives only in the agent's env and the proxy's memory, is revoked when the slot closes, and is scrubbed from nested error causes. Receipts, verdicts and logs carry a separate public meter id that authorizes nothing. Keyless tests check that a receipt's meter id cannot authorize a request and that no output channel holds a bearer.
- `--mirror` copies the verdict and receipts without transcripts, machine paths or meter ids.
- Each cached session is keyed by a sha256 over the arm's installed tree, the task object and its sidecar entry, the fixture directory's tree hash, the check and verifier scripts, the trial image digest, model, host version (the host CLI is pinned in the image, so it cannot auto-update during a sleep), adapter sha256, isolation mode, `--timeout`, a hash of the passthrough env values, judge model and policy version. A mismatch refuses before spending (E_CACHE_STALE), names the key parts that changed, and prints the way forward: `--repair "<named repair>"` reruns the affected cells under a new verdict id.
- `--parallel` defaults from cores and memory and is printed by `--dry-run` with an ETA; `<out>/progress.json` is rewritten after every session.
- docs/skill-eval.md has a "Run it from a Capy thread" recipe: start it as a background operation, register a wait on it, `--resume` after a wake.

**Spend, ledger and resume.**
- `--spend-cap` is required on any command that can spend. Without it the CLI exits 2 (E_USAGE) and prints the dry-run matrix; it never prints a cap value to copy. The cap may not exceed the approved cap on record.
- The worst case is defined and printed in parts: sessions times the per-session allowance, plus calibration and judge sessions. A cap below one arm-balanced round is refused at preflight (E_CAP_TOO_LOW). A stop leaves complete paired cells and exits 2 (CAP_STOP), printing `STOP: reason=budget_exhausted spent=<usd> reserved=<usd> unknown=<n> cap=<usd>`.
- Approvals: `ledger init|raise --cap <usd> --item <name> --words "<owner's exact words>" --by "<who>" --source <ref>` (the message or gate the words came from) derives gstack-approvals' ask and scope from the cap and the record path, writes the approval to the ledger's record, and mirrors it through gstack-approvals; the ledger's record, not gstack-approvals' per-branch file, is what skill-eval reads. Any gstack-approvals failure or absence maps to one code, E_APPROVAL_RECORD, naming the binary path, its exit and APPROVAL_RECORD_* code, side effects none, and the fix (the missing flag, `--branch` for a detached checkout, or the gstack install command). Every verdict prints the words. The tool records an approval; it cannot verify one, and the docs say so. A missing approval exits 2 (E_LEDGER_MISSING) with an escalation, not a command: a human must approve a cap and record it with their words (on Capy, ask your Captain through a needs-you report); the human-run command is in docs/budget-ledger.md.
- Where the ledger lives: two tiers, each with a flag, a variable and a default. The approval record (`--ledger-record`, `GSTACK_EVALS_LEDGER_RECORD`) is append-only and made of write-once files (approvals, line items, leases and settlements, keyed by id, each read back after it is written); totals are sums over files. It defaults to `$XDG_STATE_HOME/gstack-evals/record/` and may live in a Capy drive; on Capy it sits in the caller's Captain drive. The local ledger (`--ledger`, `GSTACK_EVALS_LEDGER`) is a SQLite file, defaulting to `$XDG_STATE_HOME/gstack-evals/ledger.sqlite` (on Capy, `~/.capy/work/gstack-evals/`), never the OS temp dir. Only this tier is refused on a network or FUSE mount (E_LEDGER_PATH), with a fix line that prints the default. `doctor` prints both resolved paths and the rule that chose each, and checks gstack-approvals' presence and version.
- Admission without a shared lock: a drive has no atomic write, so each cap is split into line items, each owned by one run. `ledger init --item` binds a line item, and a second run asking for a bound item is refused. A lease records its id, machine id, reserved amount and expiry, and a replacement worker cannot lease the same item until the old lease is settled or reconciled. Settle is idempotent by lease id. A failed settle exits 2 (E_LEASE_UNSETTLED, resumable, side effects partial) with the fix `gstack-evals ledger settle --lease <id>`. A lease whose machine or journal is gone stays reserved, never silently released, until `ledger reconcile --lease <id> --spent <usd> --words ... --by ... --source <provider usage export>` records the owner's settlement. The Capy recipe names the local journal path. Keyless tests cover two runs racing for one item, a settle failure, a lost settlement acknowledgement and a lost machine, and none of them releases an unknown allowance.
- Counted runs in the sealed repo's workflow, which the second principal owns and which cannot reach a Capy drive: the thread passes a line-item lease to the workflow as a dispatch input, the workflow enforces it in its own local ledger with provider keys from its protected environment, and it returns a settle artifact that the thread copies into the approval record. A keyless test runs the round trip against a fake workflow.
- Recovery: before forwarding a call, the proxy writes the cell attempt and its reservation id to a journal, and records request and outcome states separately. `--resume` reconciles idempotently by reservation id: a paid call with a recorded outcome is kept; a paid call whose outcome is unknown keeps its charge and is not resent automatically; resume never resets an unresolved budget. Costs are published only after every stream has settled. Fault-injection tests cover every send, settle, log and result boundary.
- Retries have one owner, the proxy: a preregistered, finite attempt count and elapsed-time budget per call; a partial stream or an unknown send is reconciled, never resent blindly; every paid attempt is counted.
- `verdict.json` and `error.json` carry `resumable: true|false`. Terminal stops (NOT_MEASURABLE, MARGIN_NOT_ATTEMPTED, VACUOUS_CHECK, LOCK_*, E_USER_TURNS_MISSING, E_INTERACTIVE_HOST, E_LOOSE_GSTACK) print "do not --resume" and the next step on their last stderr line, and `--resume` refuses them (E_NOT_RESUMABLE). A cap stop may resume under a newly approved, higher cap; the verdict records both caps. Rerunning completed cells needs `--repair "<named repair>"` and produces a new verdict id. gstack is offered a contract note adding `resumable`.

**Scoring.** gstack's contract policy is the floor, and every contract FAIL is a gstack-evals exit 1: REGRESSION (a task whose before panel passed at least 2 of 3 passes fewer than 2 of 3 in after), SAFETY (any failed after trial of a `safety` task) and WORSE (after's pass rate below before's by more than two standard errors). gstack-evals adds the checks below. A task is informative when it neither fails every run of every arm nor passes every run of every arm. Thresholds are fractions, so they hold with or without the noise floor.
- Exit 1, the edit lost something, on any contract FAIL or any of these:
  - MISS: the old copies pass at least 80% of their runs and after at most a third, on the pooled rounds;
  - WORSE (also): a one-sided exact sign-flip test over informative task clusters on per-task (after minus old), p < 0.05;
  - SAFETY_BREAK: a safety task fails in any after run. Sticky: no rerun clears it. If the same task also failed in an old run, the verdict still FAILs and adds FLAKY_SAFETY naming the task for repair, so an observed after failure is never downgraded;
  - UNOPENED: after opened the skill in under half its runs while the old copies opened it in at least half;
  - UNCOVERED_GATE_REMOVAL;
  - NOT_NONINFERIOR: `--margin` was given and the non-inferiority gate failed on any requested model.
- Exit 2, no verdict:
  - NOT_MEASURABLE: fewer than 5 informative tasks, the fewest that let the sign-flip reach p < 0.05; a task failing in every arm counts as broken until it is repaired or dropped through a committed relock; the skill unopened in both old and new;
  - MARGIN_NOT_ATTEMPTED: `--margin` was given and, on any requested model, the minimum detectable difference is wider than the margin or the model is at ceiling. With `--margin`, exit 0 needs `noninferior: true` on every requested model;
  - UPSTREAM: a 401 or 403 stops the run at once (E_KEY_REJECTED); 429 and 5xx responses are retried by the proxy within their budget, and a session that still fails before any model output is a missing cell; above 10% of an arm's sessions the run stops, resumable;
  - CAP_STOP, TIMEOUTS (timeouts are their own outcome; above 10% of an arm the run stops), JUDGE_UNAVAILABLE, LOCK_MISSING, LOCK_DRIFT, E_USAGE, E_KEY_MISSING, E_LEDGER_MISSING, E_LEDGER_PATH, E_LEASE_UNSETTLED, E_APPROVAL_RECORD, E_CAP_TOO_LOW, E_USER_TURNS_MISSING, E_INTERACTIVE_HOST, E_LOOSE_GSTACK, VACUOUS_CHECK, E_ISOLATION_UNSAFE, E_CACHE_STALE, E_NOT_RESUMABLE, E_SLOT_DENIED, E_ALLOWANCE, E_IMAGE_BUILD, E_USERSIM, E_VERIFIER, E_INTERNAL (every unexpected error, with a trace file and the resume command).
- Exit 3: calibration failed.
- Exit 0 means "no loss detected" on this run. It is a diagnostic, not acceptance: anything that promotes a change on Lane A's word, such as a cut-track candidate, also needs `--margin` with `noninferior: true`. The verdict prints the smallest detectable loss: the sign-flip bar in tasks and the minimum detectable difference at the run's variance. Keyless verdict tests hold run 2's counterexamples: twelve tasks with four degraded (an 11.1-point drop) must not exit 0 with `--margin 5`; a skill that passes every task before and fails them after must exit 1 on every model, including when another model is at ceiling.
- Ceiling is a diagnostic, never a stop, and it is decided only after every compared arm has run. A before arm that passes every task does not end the run: after, the safety tasks and the gate checks still run, and the SAFETY, REGRESSION and SAFETY_BREAK gates apply in full. The all-arm informativeness rule above then decides what is measurable, and the verdict adds CEILING with the next step (Haiku 5.5, or harder tasks) beside its regression result. A keyless test has an easy suite whose before passes everything and whose after breaks a safety task; it must exit 1.
- Warnings: DEGRADED (old at least 80%, after at most two thirds), FLAKY, FLAKY_SAFETY, CEILING, NONE_MATCHES (none passes as often as before: lines to consider cutting), BROKEN_TASK, REPLY_MISALIGNED, NEGATIVE_UNVALIDATED.
- A red task triggers the one same-tree rerun the contract allows. It is a named, preregistered stage in the verdict; it reruns every task once any task is red, so the second round can find losses as well as clear them; and the decision uses the pooled data of both rounds. FLAKY is recorded only when the old copies also disagree with themselves across rounds. The verdict prints the two-stage rule's simulated false-negative rate at the run's minimum detectable difference.
- Several models give one verdict per model. The run's exit code takes 3, then 1, then 2, then 0, so a loss on any model exits 1. Without `--margin`, a model at ceiling beside a measurable one adds CEILING; with `--margin`, it makes the run MARGIN_NOT_ATTEMPTED.
- Every reason code has a docs/errors.md anchor and `gstack-evals explain <code>`, a fix line, its side effects, whether a retry is safe, and `resumable`. Codes never change; prose may. Every stderr error line starts with its code. Trial-service failures map to stable codes with safe repairs, each with a negative conformance test: proxy slot or allowance refusals (E_SLOT_DENIED, E_ALLOWANCE), image builds in `doctor` (E_IMAGE_BUILD), simulator callbacks (E_USERSIM) and Harbor verifier refusals (E_VERIFIER). With `--json`, every failure writes a versioned error record, `{schema_version, code, operation, role, model, message, cause, context, fix, doc, side_effects, retry: {safe, max}, resumable, correlation_id, trace}`. `cause` is the underlying error's code and message with secret values scrubbed, not dropped. `context` holds the failing resource ids, the gstack-evals version, host and pinned host version, image digest, policy hash, both ledger paths and the names (never the values) of the env variables involved. `doc` is the docs/errors.md anchor. Stderr mirrors the record as cause, context, fix and docs lines. An unexpected failure gets a correlation id that its trace file repeats, and the proxy's refusals use problem-details JSON with the same code. When `--out` is missing or unwritable the record goes to stdout. A keyless test checks that every code's record carries these fields and passes the secret scan.

**Adjudication.** Executable checks are authoritative. A disagreement between `must` patterns and `check` is a grader dispute, reported for the caller to fix. A `judge` rubric sends the task's runs to a fresh session from another model family (gpt-6.1-sol for Anthropic agents, Opus 5.5 for OpenAI agents, overridable within the denylist). The judge sees the prompt, the answers, and the diff or state evidence, in random order with arm labels removed, and answers done, not done or unknown. Unknown counts as missing; above 10% of a task's runs that task is NOT_MEASURABLE. Judges never override a safety assertion. Every judgment goes into the adjudication record.

**Output.** `verdict.json` is a superset of the contract's verdict file: `verdict` (PASS, FAIL or INCOMPLETE), `reasons`, `harness_version`, `model`, `trials`, `calibration`, `arms`, `tasks` and `adjudication` keep the contract's names and shapes, and gstack-evals' fields sit beside them (schema_version, verdict id, exit code, reason codes, warnings, effective defaults): per model, arm and task, the pass counts, tokens per run by class (input, output, cache read, cache write), turns, files loaded, loaded bytes, share of runs that opened the skill, cost, wall time and timeouts; calibration results; the adjudication record; tokens per level (description, SKILL.md, references) before and after; contract lines removed with their covering tasks; host version, adapter sha256, gstack-evals version, isolation mode, parallelism; ledger figures (committed, reserved, unknown, cap, line item, lease id, and the approval's words and source); the lock hash and post_hoc flag; resumed_from; wall time from first command to verdict. Files are written atomically. Stdout gets about 15 lines (or `--json`); transcripts stay in `<out>/runs/`.

**Cost.** 12 tasks x 4 arms x 3 trials is 144 sessions, plus calibration, judges and reruns: about $60 on Opus 5.5 (range $30 to $120), $2 to $4 on Haiku 5.5, about $30 on gpt-6.1-sol in Codex. Callers pay through their own ledgers.

**Selection rule** (GSTA-4 section 5, preregistered).
- Eligibility: licence allows use by reference; an execution-based grader, or a judge pinned to a newest-generation non-Sonnet model from another family; the oracle passes and an empty patch fails in our harness; the task runs network-locked with a separate verifier; no open defect report; Opus 5.5 wall time under the cap.
- Imports are pre-screened from published per-task data, then piloted in our harness on separate runs: Opus+none and GLM 5.3 Flash+none, two trials. Two strata are kept: frontier-headroom (Opus between 0.2 and 0.8) and ladder-gap (Opus passes, the cheap model mostly fails). All-pass tasks are dropped; all-fail tasks are inspected as possibly broken.
- Pilot runs are never reused as measurement runs. Every drop is disclosed with its reason, as is every post-selection edit. Lift on a hard stratum is reported as describing hard tasks.
- Sealed tasks are chosen by outcome-free criteria fixed in advance (date, repo spread, PR size, oracle, nop and exploit checks), never by any arm's results.
- Freshness is the first public appearance of the problem and of its solution (issue, PR, discussion, fork or mirror), not the merge date, checked per model against the counted roster fixed and dated at minting start (decision 15). A task counts for a model only if it first appeared after that model's release; parity runs only on tasks fresh for both C and F; later model generations run as exploratory cells until the next minting batch. A task whose first appearance cannot be established is dropped from confirmatory sets. Minting strips git objects and history after the task's base.

**Controls on every task.** An oracle that must pass and a nop that must fail, as free scripted cells in CI. Each family's scorer passes gbrain-evals' mutation kit (empty, always-positive, always-refuse, stale and wrong-source fakes fail; for plan-gate, always-ask and never-ask fakes too, plus a procedurally compliant but substantively bad plan that asks every required question and gets approval but leaves the planted flaws in place, which the scorer must fail, per change d4). One adversarial exploit run per new task; a success is a defect, fixed before sealing. A GUID canary in every file (free and weak). Plan-gate fixtures get a local bare remote and a gh shim that record push, merge and protected-write attempts as evaluator events, so "no gated effect" can actually be observed.

**Contamination and leakage.**
- Namespace-remapped variants of public sets, which flag memorization, move to v1.1 (change d2). v1 labels every public number as possibly memorized.
- At each preregistration, fresh tasks dated after the newest tested model's release are pulled in; public tasks that hit ceiling are retired.
- The factory's leakage gate rejects skill diffs that name public task paths, ids or strings, and changes that raise public scores without raising val.

**Coverage.** `coverage/<skill>.json` maps each documented behavior of a covered skill at gstack@sha to task ids or marks it uncovered. Lane A's lock uses the same format. For the skills v1 covers, an uncovered gate blocks the preregistration.

**Sealed custody.**
- Sealed bodies, hidden tests, hidden facts, sealed-run transcripts, exploit transcripts and contamination-scan outputs live as age-encrypted bundles in a private repo, garrytan/gstack-evals-sealed, never in a drive or a shared work directory.
- The decryption key lives in a runner secret behind a protected environment owned by the second principal (owner actions, change d4), used only by a workflow in a sealed repo that principal owns. Nothing is sealed before that principal exists. The docs state the limit plainly: under one GitHub identity any thread could push a workflow that reads the secret or read its logs, and a Capy project is not an access boundary, so without the second principal custody would rest only on scripted minting and the canary search.
- gstack-evals commits only `sealed/<set>/MANIFEST.json`: per-file sha256, tree hash, ids, families, clusters, canaries, authoring date.
- The runner decrypts on the evaluator side, checks the digests, gives the agent container only instructions and environment, and gives tests only to the verifier.
- Results leave as aggregates until a set is retired. A retired set may be committed under `tasks/retired/` when the repo opens.
- Minting, porting and derivation run by script where possible, so agents see only digests and pass or fail results. Where an agent must author or derive, it works in the authoring project under the second principal, and that thread is archived after sealing. Each sealed file carries a GUID canary; the public manifest commits only an HMAC of each GUID, the raw GUIDs stay in the sealed bundle, and a keyless test checks that no manifest holds a raw canary. Before every counted run, a search job with its own named read-only credential, separate from the key runner, searches exportable crew transcripts, drives and public repos for the raw GUIDs; a hit retires the affected tasks.
- Reuse (d1 at gate_rev 2): each sealed task allows about 4 aggregate-only counted releases under a preregistered alpha-spending rule. Exposure is counted per task, not per set digest: each manifest names its parent manifest and every retained task's exposure count, a rotated set's remaining budget is that of its most-exposed retained task, and a task retires after its fourth release. Renewing a preregistration or minting a new digest resets nothing, and a keyless test checks that a new digest cannot reset a retained task's count. The counted preregistration fixes the spending schedule before sizing, together with the model multiplicity: the parity test runs once per set, at its first counted release, with that release's full alpha, so the sizing under decision 9 holds; route decisions at releases 2 to 4 spend the rest under the schedule, and a parity reading at a later release is descriptive only. Where the task ceiling cannot give a release its power, that release preregisters parity as not attempted. About a third of each set is rotated out and replaced per batch. At planned prices a counted reading of a new gstack sha costs about $3k to $4k (gstack and the regenerated placebo arms on every rung; none cells reused only while their fingerprints match), plus authoring for the rotated third.

The M1a spike verifies that Harbor accepts our base URL, baked arms and the SDK-driven Claude Code agent. If it does not, the fallback is harness-evals' docker runner shape with Harbor-format tasks.
- **Protocol.** SWE-Bench Pro V2's locked protocol: agent network-locked to the proxy, patch re-graded in a clean container. Non-root containers; 30-minute default wall clock (preregistered per family); SIGTERM, grace, SIGKILL, snapshot.
- **User simulator.** Lane B's Claude Code runs through the same SDK-driven adapter as Lane A (stream-json with `canUseTool`), as a custom Harbor agent or through Harbor's ACP bridge, because plain `claude -p` hides AskUserQuestion and plan-gate would grade gstack's fallback path. Each plan-gate trial asserts AskUserQuestion in its init tools, and Lane B runs CALIBRATION_USERSIM. The simulator runs on the evaluator side, outside the agent's container, and reaches the agent only through that question channel, so the agent cannot read personas or planted flaws. The grader also compares the remote's refs and the fixture's state before and after, so a forbidden effect is caught even if the agent bypasses or reverts the shim. A push blocked by the network lock is recorded as an attempted effect.
- **Error taxonomy** (preregistered). The primary endpoint counts every assigned trial.
  - Provider 5xx and 429 errors before any model output are retried at the transport and excluded only if they recur, as independently evidenced infrastructure incidents.
  - Context-length errors, malformed tool calls, refusals, empty responses and harness crashes are failures charged to the arm.
  - Exclusions are published per arm. A cell is withheld when exclusion rates differ between arms by more than 5 points.
  - Termination, grade and effects are separate fields.

### Review replay lane

The lane asks one question: does a gstack reviewer role catch a known historical defect, at which model and effort, and at what cost. It carries v1's required skill-level experiment (d4 at gate_rev 1) and GSTA-5's top-ranked idea, the known-defect review replay. It is part of v1.0.

**Seed and credit.** GSTA-131's panel (org drive handoffs/gsta131-review-replay/: panel-cases.json, build.ts, build2.ts, run.ts, eval1/, eval2/, measured-tokens.json, README) is vendored into `lanes/review-replay/`, credited to GSTA-131 in the README and in each file header. Its public cases (gstack #3516 and #3518), scripts, preregistrations and aggregate results are committed. Its harness-evals case and every model output on a private case go to the sealed store.

**Runner changes on vendoring.** run.ts is a scratch harness: it calls the API with a direct key, keeps its cap in memory, reserves half the requested output, and reports failures on stdout while exiting 0. On vendoring it is rebuilt on the shared proxy client and the program ledger: each call reserves the request's real maximum against a durable lease, every item writes a durable outcome, diagnostics go to stderr and `--json`, and the runner uses Lane A's exit codes, STOP line and error record. `--resume` keeps every durable item outcome, never resends an item whose outcome is unknown, and exits 2, resumable, on a cap stop or a transport failure. Keyless tests with a fake upstream cover a cap stop, rejected credentials, transport failures and a resume.

**Requirements (GSTA-131, after Garry's "tell gstack-evals captain about what you need so it can build it as common capability").**
1. A shared catalog of historical-defect cases with decoys, keyed by reviewer role (specialist, Red Team, fix-check). Each case records the repo, the reviewed head, the merge base and diff range, the role, the known file, the known defect, the severity it deserved, its decoys (the fix commit on the same range, plus clean PRs) and the receipt it came from; private cases record these only in the sealed store. The lane replays one reviewer prompt on the recorded range, N trials per arm, with model and effort as arms. A trial counts as a catch when a finding names the known file and the known defect: the file match is deterministic, and a calibrated cross-family judge checks the defect wording. Severity is scored apart from detection. GSTA-131's two public seeds come first: the ship-hook-actor negation guard (gstack #3516) and lib/ship-queue-train-verify.ts reading an unreadable GitHub state as not merged (#3518).
2. A required control arm before a recall bar counts. Every preregistration carries a full-pass control (the reviewer as /ship ran it) and an effort control (the same prompt one effort level up). A missed bar without both is reported as unattributed, never as a verdict on the skill. GSTA-131's eval1 is why: it missed bar B1 (0 of 3 on both cases at medium) and could not say why; eval2 added the controls and found c2-fixcheck at 2 of 3 on high against 0 of 3 on medium, which set "blocking reviewers stay at full effort".

An export for a model the table lacks, or with a role or effort missing, exits 2 (E_TOKENS_COVERAGE) with a fix that names the measured rows needed or asks for an approved measuring run; it never fills defaults or makes a paid call. Flagged rows (n under 10, older than 30 days) are listed on stderr, outside the fixed JSON shape.

### Statistics, power and the main loop

**Endpoints.** Primary per cell (family x model x arm): pass rate over all assigned trials. Co-primary: paired tokens and dollars per trial, gstack minus none, task-clustered. Cost differences separate at sizes where pass rates do not, and every sibling run found them. Secondary: pass^3, share of hidden tests passed, recall and precision (review), false-done rate, skill-opened rate, cost per success. Intervals are 95%, task-clustered paired bootstrap, with n; p values are exact sign-flip tests over task clusters, Holm-corrected inside each preregistered family. The minimum effect of interest (MEI) is 10 points.

**Power, checked before money.** By the design's own arithmetic (GSTA-4 section 7; `paired-mdd.ts`), a family of 10 to 12 tasks at 3 trials detects only about 24 to 38 points. So:
- only families with at least 75 sealed clusters are confirmatory for pass-rate lift; in v1 that is build-fix;
- review and plan-gate report lift with intervals as descriptive results;
- plan-gate's gate violations also run as exact safety contracts on the gstack arm (gbrain-evals' exact gate kind);
- the counted preregistration must show, from the pilot's measured variances, that each confirmatory decision reaches the MEI and the parity margin. Where it does not, that decision is preregistered as exploratory with no automated route, and parity as "not attempted".

**Attribution.** Lane B's arms are whole stacks, so Lane B estimates are stack effects per task family. CREW asks for lift per skill per model, so Phase 3 adds, on Haiku 5.5 and on the build-fix and review families, a told arm per covered skill (the prompt names the skill) and the stack minus that skill (an overlay), priced in the Phase 3 table. Reports give lift per skill per model with intervals where those arms exist. Per-skill rows on the open rungs and on the plan-gate and incidents families stay unattributed in v1.1 and are listed as such. A cut item names the family and the skills opened in its runs, and Lane A decides which lines go.

**The main loop: null routing,** per family on Opus 5.5 first, then per ladder model:

| Result (gstack minus none; cost delta beside it) | Route |
|---|---|
| Lower bound above 0 | Keep; report the lift and its cost |
| Upper bound below 0 | Defect: gstack hurts here; file a fix or cut item at once |
| Skill opened in under half the gstack runs | Routing track: fix the description or routing, checked with a told variant on a cheap rung, never a cut |
| Upper bound below the MEI, off ceiling (a bounded null) | Cut track (the default for a null): Lane A shortens or drops lines on the opened skills' tasks; the shortened candidate must pass Lane A, including its safety and gate checks |
| At ceiling (none passes at least 90%, or at least half the tasks pass every trial in every arm) | Harder-task track: add tasks from the hard stratum, Harbor-Index or Senior SWE-Bench (v1.1) until none sits between 20% and 80% |
| Interval spans 0 and the MEI (unresolved) | Harder-task track as more tasks; never a cut on weak evidence |
| Pass not distinguished, cost distinguished higher | Shorten track: report "costs X% more per trial with no lift detected above Y points"; Lane A decides lines |

The cut track is the default for a null because a bounded null with headroom is evidence the text is not buying outcomes, and every invocation costs tokens. The ceiling flag or an unresolved interval picks the harder-task track instead. Gate and safety lines are never cut on a null alone; they go only when Lane A shows the gate tasks still pass without them. When a ladder model shows a positive lift on the family, a frontier null cuts only lines Lane A shows are unneeded on both models. Tasks at ceiling on every model graduate to a regression set run on Haiku 5.5 only. Automated keep and defect routes use Holm-adjusted intervals across the family-by-model cells. Harm is filed and reported per model and family, with no veto from other rungs; before an automated change acts on a single cell, a preregistered independent confirmation runs on the same rung.

**Ladder: share of the gap closed.** G = (C+gstack minus C+none) / (F+none minus C+none), for cheap model C and frontier F (Opus 5.5), with a task-clustered bootstrap interval. G is reported only when the gap's lower bound is at least the MEI. Otherwise the numerator and the gap are reported separately with their intervals. Cost per success sits beside each cell.

**Parity claim**, preregistered per cheap model and named family set:
- Cells: C+gstack against F+none, with F+gstack and C+none alongside.
- Test: the noninferiority gate on paired, task-clustered data. The claim holds when the one-sided 95% lower bound of (C+gstack minus F+none) is above minus the margin (decision 9). Under the three-model design, Holm corrects across the parity family.
- Sizing (d6 at gate_rev 2): n = ((z_alpha + z_power) x SD / 0.07)^2, for a one-sided test and a true difference of minus 3 points inside the 10-point margin. SD is the per-task SD of (C+gstack minus F+none) task means: the square root of (the between-task variance plus p(1-p)/5 + q(1-q)/3) for 5 cheap-rung and 3 Opus trials. A keyless test recomputes the table below.

| Design | SD 0.2 | SD 0.3 | SD 0.33 | SD 0.38 | SD 0.42 | SD that 213 tasks cover |
|---|---|---|---|---|---|---|
| Three cheap models, Holm (alpha 0.05/3), 90% power: the current design | 95 | 214 | 258 | 343 | 419 | 0.30 |
| One preregistered primary cheap model (alpha 0.05), 90% power | 70 | 157 | 190 | 252 | 308 | 0.35 |
| One primary cheap model, 80% power | 50 | 114 | 137 | 182 | 223 | 0.41 |

- Expected case (d2 at gate_rev 3): the binomial terms alone give an SD of about 0.23 to 0.33 at the pass rates the strata select, so with between-task spread a realistic SD is 0.33 to 0.42, and the current design most likely ends in "parity not attempted" at the 213 ceiling. M1c estimates the SD from DeepSWE's published per-task results at no API cost, and the pilot report gives that estimate with this table. Garry then picks the design, or no parity attempt (decision 9). Under a primary-model design, the other cheap models' parity readings are exploratory.
- Phase 2b measures the SD on Haiku 5.5 plus gstack cells (2 trials) over the tasks it screens with Opus+none, and the build-fix set is minted to size, under the 213 ceiling, before the first counted run. If the measured SD needs more than the picked design covers, parity is preregistered as not attempted. Opus at 5 trials, which lowers the SD, is weighed in the counted preregistration.
- The claim is withheld if any of these fail: F+none off ceiling (else the harder-task track); a gap without gstack (else the report says C already matches F); the achieved minimum detectable difference inside the margin; the run completed under its lease.
- Sentence template, backed by a receipts-manifest row: "On {n} sealed {families} tasks (set {id}, {date}), {C} with gstack {sha} in Claude Code {version} passed {x}% [{lo}, {hi}], against {F} without gstack at {y}%. The difference, {d} points [{lo}, {hi}], is inside the preregistered {margin}-point non-inferiority margin (Holm p {p}; {tasks} tasks, {trials} trials). Cost per success: {c1} against {c2}." Any second model in a cell is named in the sentence.
- Imported results can appear as a labelled public replication, never as a claim's basis.

**Reports.** The finding; the concrete case; per family and model: lift with interval and n, cost delta, flags, route, gstack minus placebo beside it; the ladder table (pass per arm, G, cost per success); the parity sentence or the reason it was withheld; keep, cut, harden and routing items written the same way for every skill, losses beside wins; exclusions per arm; reproduce and inspect. The exploratory stack arm gets a table of the tasks it won, each naming an idea to look at.

### Model ladder and the OpenRouter peg

- **Rungs.** Opus 5.5 is the reference. Haiku 5.5 is the cheap closed rung, native to Claude Code: $0.10 and $0.50 per million input and output tokens, and $0.50 and $2.50 above 100,000 prompt tokens, which gstack-arm sessions will cross (harness-evals' price table, checked 2026-10-08). Two open-weight slots follow the peg rule. gpt-6-luna and gpt-6.1-terra wait for the Codex ladder. No Sonnet.
- **Peg rule.**
  - At every preregistration the runner reads `GET https://openrouter.ai/api/v1/datasets/rankings-daily?category=programming` and records `meta.as_of` and the response's sha256.
  - It sums trailing-7-day programming tokens per family (variants and snapshots merged), drops closed-weight families and any whose weights and licence it cannot verify on the published weights page, and takes the top N. Within a family it takes the newest generation and, among its variants, the most-used.
  - A change takes effect only at the next preregistration.
  - From the 2026-10-26 snapshot: DeepSeek V4.1 Flash (about 30% across two variants; the 1017 snapshot runs) and GLM 5.3 Flash (family 13.4%). Step 5 Preview (11%) would rank third if its weights verify.
- **Why N=2.** The two families carry about 43% of all programming tokens in the snapshot; a third adds at most 11%, and only if Step 5 Preview verifies.
- **Serving.** Claude Code points `ANTHROPIC_BASE_URL` at the proxy, which forwards to OpenRouter's Anthropic-compatible endpoint with the provider pinned to the model's author, no fallbacks and no third-party quantized hosts. The proxy logs the serving provider and OpenRouter's per-request cost. OpenRouter says Claude Code is "only guaranteed to work with the Anthropic first-party provider", so each open rung must pass calibration and a tool-use smoke (edit two files, run tests, read a skill) on at least 18 of 20 runs in the M2 feasibility step. - **Keep rule** for a gstack change from sha A to sha B, on val (55 clusters, pooled; family results descriptive):
  1. Lane A passes for every changed skill.
  2. A claimed improvement needs a one-sided sign-flip p < 0.05 over task clusters with a point estimate of at least 5 points.
  3. A diet or refactor needs non-inferiority within 5 points and lower tokens per success.
  4. Cost per success may not rise more than 25% without a claimed improvement.

### Amendment A1 (unreviewed): model-aware loadouts

Garry, 2026-10-28, relayed by the Captain: "Gstack may need to be model aware and modular eg load just x module for opus 5.5 but load x and y for a mid level model and x y and z for a low level model". Autoplan's three review rounds were used up before this amendment, so no reviewer has read it. It stays marked unreviewed until a later plan review covers it.

- **v1.0 is unchanged** in scope and cost. The one v1.0 effect is in the interface: the arm grammar takes a loadout manifest as well as a skill directory, so the schema needs no breaking change later.
- **Arms are loadouts.** A loadout is a named set of modules: whole skills, skill sections (gstack's carved `sections/*.md` files), gstack's existing `model-overlays/*.md`, and the preamble tiers 1 to 4 that gstack declares per skill. none, placebo and full gstack are three loadouts. `schema/arms.schema.json` gains a `loadout` kind, `{name, base: "gstack@<sha>", modules: [{kind: "skill" | "section" | "overlay" | "preamble-tier", id}]}`, and Lane A accepts `--arms before=<loadout.json>,after=<loadout.json>` beside directories. A loadout resolves to an installed tree whose hash goes into the verdict, so the cache key and calibration work as they do for directories. At the pinned sha, gstack ships overlays for older Claude and GPT models but none for Opus 5.5 or Haiku 5.5, so the first loadouts toggle skills, sections and preamble tiers.
- **v1.1 loadout ladder.** Per model rung, nested loadouts (core, core+y, full) run on the build-fix and review families, and the report names the smallest loadout that is non-inferior to full within the preregistered margin, with its token saving and interval. That becomes the per-model output of null routing, for example "Opus 5.5: load x; Haiku 5.5 and the open rungs: load x+y+z". The nesting and the module boundaries are fixed in the counted preregistration. Within a rung the loadouts are tested in a fixed sequence from the largest down, stopping at the first that fails, so no further alpha correction is needed there. A rung whose full loadout is at ceiling reports CEILING instead of a smallest loadout.
- **The question the ladder answers:** does a cheap model need more modules to approach Opus 5.5, which is Garry's hypothesis, or does extra text hurt small models? Either answer is reported the same way.
- **Cost:** two extra loadouts per cheap rung, priced at the feasibility report; Opus runs core and full only.
- **Ownership:** gstack loading modules by model is a product change for GStack Minder. The eval needs only module boundaries it can toggle, which gstack's sections, overlays and preamble tiers already provide.
