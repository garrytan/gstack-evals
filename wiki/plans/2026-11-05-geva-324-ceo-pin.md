# CEO outcome eval pin

This post pins the CEO outcome eval to one build commit. The eval is the preregistration (#214) as its guard amendment (#217), ladder amendment (#222) and stop-label amendment (#225) leave it. Nothing here spends.

The post changes no frozen rule, threshold, arm, size or verdict rule. Each line restates a frozen rule, a Captain cover recorded on #225 or #229, or a fact, with its source. Two items are new, and the Captain set both as the condition for #230's fail-closed direction: the smoke findings check (section 4) and a report-only disagreement count (section 7, note 9). Line numbers in src/, lanes/ and tests/ are at the build commit unless marked.

## 1. The pin

- **Build commit:** 715c6594851c558edcd64f97e6627ef55a7cbbec (tree a969577910cd906c47b66878dfc70a6d1028c397), the squash merge of #230 into main. Run threads build and run gstack-evals from this commit only (section 5, rule 1).
- **The exposure fix.** #230 changes the autoplan arm's `findings_written` check (`ceoReviewText`, `writeTargets` and a new `commandWords` helper in src/trial/review/ceo-exposure.ts) and adds an on-disk copy in src/trial/trial.ts and src/trial/review/run.ts. It makes these changes:
  1. **Backslashes.** A Bash write whose first line holds a backslash outside single quotes reads as writing no Findings (ceo-exposure.ts:163), the rule `segments()` already uses for the handoff call. This closes Capy finding 01M6P90MV7W5RDGHSQATBFVSAA, which #229 left open, in both its cases: `printf \-v x '...' > <AP>/ceo-review.md` read `findings_written` true and now reads false, and an escaped double quote in the first line still reads false.
  2. **Escapes.** A `\n` reads as a newline only where bash expands it: in printf's format word, and in echo's text when `-e` is in force, up to echo's `\c`. A `\\` pair decodes first. Plain echo and printf's arguments write a literal `\n`.
  3. **Command words.** The command and its arguments are the shell words left after every redirection is cut (`commandWords`), so a redirection may sit anywhere. tee's file operands come from the same words, in a piped tee too. Only tee and a cat with no file operand take their text from a heredoc body. For echo, printf or any other command, a filter such as sed included, the body counts for nothing.
  4. **Fail-closed rule set.** Each of these reads unwritten: a tee option other than `-a`; any input redirect other than one plain heredoc; a second stdout target (`2>` is not one); a head that redirects stdout into a piped tee, or a piped tee with an input redirect; and an unquoted heredoc body that holds a backslash, a backtick or `$(`.
  5. **On-disk copy.** Before a ceo-outcome session's work dir is removed, every regular file named ceo-review.md under it is copied byte for byte into the session's host/ceo-review/ at its relative path (trial.ts:149-151, run.ts:459). Symlinks are not followed. `copyNamed` keeps going past an unreadable directory or a failed copy and records each failure in the session's trial.json `logs.copy_out` (trial.ts:105-124). The receipts sink gets each session's host/ceo-review/ beside host/transcript.ndjson (run.ts:338-339). `findings_written` keeps its transcript definition; the copy exists only for the checks in sections 4 and 7.
- Changes 1 and 4 also make some real writes read false, such as a double-quoted first line with a backslash (`printf "## Findings\nNone.\n"` or `echo -e "..."`). The Captain accepted that fail-closed direction on the condition that the smoke sessions check it (section 4).
- **The exposure digest.** #230 changed the detector code before this pin, so `CEO_EXPOSURE_SHA256`, the sha256 of ceo-exposure.ts's own bytes (ceo-exposure.ts:38), moved from 022021af32eacfd6180b31f9dc0a112c7838425e57ef2c9f4fe0449122ba7796 before #230 to c0498fa065cb3c50f44cd93d78417577e706a4b0ddd3c491c9ffcb0b7718dd19 at 715c659; that is no rule change, because no paid run has written rows and the ladder amendment only listed the exposure detectors among what it left alone (its README:163).
- **Frozen file pins.** The scorer: the stop-label amendment's ceo-rule.ts.txt, sha256 2222e0cfa65f9f105d6645a70fc6a4bed67d9f0f75033d6e935cdebb7fcaf179. The template: the preregistration's template.txt, sha256 b7c4c11020eff83695534cb32f10f019824b8775d92a1b1237ce72aeea05d862, pinned in tests/trial/review/ceo-outcome.test.ts:58. The judge brief: the ladder amendment's judge-brief.md, sha256 d7b3dce1498e01e874f1dae024ac90e79e5ff5e3af12cc5ed37e2f8a48a14fb5, pinned in lanes/review-noloss/judge-run.ts:420. The stock list: the ladder amendment's stock-list.txt, sha256 9ecbc78e696836bd11c3e89df1cc1cb0b0e28940b92e7dd3a96846224e47fe3c, pinned in src/trial/review/ceo-cli.ts:45.

The eleven readings:

2. **A malformed last block** counts as no block written. A session that ended on a timeout, the turn cap or the allowance then reads no-block, and one that ended on a CLI failure, an infra failure or the background deadline reads gap.
3. **A completed session with no model output** follows section 6's table: the follow-up turn, then scored or no-block.

## 4. Start order

Stage 1's smoke sessions run first. `gstack-evals ceo rows --checks` must pass on their transcripts before any stage 1 none item opens a lease. It passes, and exits 0, only when every session the given runs hold is in the journal, has a readable transcript and a parsable last block, holds the end state section 6's table gives, is scored, and on gstack-auto and gstack-forced passes every check of its exposure detector. Otherwise it exits 1 and names each failing session with its first failed check. If it fails, stage 1 stops and goes to the Captain. (Stop-label amendment, rule line 14, README:73.)

**Smoke findings check.** The Captain set this check as the condition for #230's fail-closed direction. It runs before stage 1, on every smoke session that has a `findings_written` check (the gstack-auto sessions; `ceo rows --checks` prints it per session, ceo-cli.ts:305 and :374).

- The run thread compares each session's `findings_written` with the ceo-review.md copies in that session's host/ceo-review/ under the run's out dir (section 1, change 5). On disk, a session counts as written when a copy holds a line that the detector's own Findings pattern matches (FINDINGS, ceo-exposure.ts:70: "## Findings" after at most three spaces).
- The check reads the out dir, never the receipts sink. The sink merges and never deletes (copyToSink, src/trial/durable.ts:96), so after a `--repair` rerun it can keep a stale copy. The out dir's session dir is cleared before each session runs (run.ts:450).
- A disagreement in either direction stops the run before stage 1, and the case goes to the Captain (GSTA-2). A missing copy where `findings_written` reads true is a disagreement, so a file a session wrote outside its work dir shows up as one.
- A non-empty `logs.copy_out` in any smoke session's trial.json also stops the run before stage 1, because a failed copy leaves no file and the work dir is removed afterwards (trial.ts:149-153).

## 5. Operator rules

1. **Build from the pinned commit only.** Runs and rows build from 715c659 only, so the parser and the exposure detectors can't change between builds (#225, open note 15). Since #229, rows.json also records `exposure_sha256` (ceo-cli.ts:395), and packets and readings refuse rows from another digest (ceo-cli.ts:425).
2. **Check the units dir.** Before rows or readings runs, the run thread checks the units dir against the custody addendum's digests (#225, open notes 16 and 23). Since #229, rows, packets and readings also refuse a `--units` dir that doesn't hash to the `catalogs_sha256` the run's units.json recorded (ceo-cli.ts:122-128).
3. **Never `--resume` a cell that stops.json lists.** A cap stop is never retried (#225, open note 17; #214, section 14, Stops). Since #229, a resume also carries such a cell, with its settled spend, instead of rerunning it (run.ts:428).
4. **No `--resume` after a runner or machine loss without the Captain's approval and a ledger check first** (#229, Review notes, cap-stop journaling; #229, Attention, row 8). A cap-stopped cell is not journaled (run.ts:495), and stops.json is written only when the run ends (run.ts:625). A run lost mid-round leaves no record of its cap-stopped cells, so a plain resume would rerun them.

## 6. The suite file

The stage 1 suite file's sha256 (the suite binding's `sha256` field, lanes/review-noloss/suite.ts:101) is frozen before the first smoke run and recorded in the custody addendum, which posts the suite's digests after B2 builds the suite and before the first smoke run. Each ceo-outcome run records it in units.json as part of its suite binding (run.ts:431), and a binding that differs refuses the resume and rows (#229, Review notes, suite-file binding; ceo-cli.ts:139). A suite-only edit after the first smoke would stop both.

## 7. Run notes

The Captain accepted notes 1 to 7 on #229 as notes, not fixes (#229, Review notes and Approvals). Note 8 is a review note on the same PR. Notes 9 and 10 come from #230.

1. **Cap-stop journaling** (run.ts:495): a crash rerun after a cap stop is not journaled. Section 5, rule 4 covers it.
2. **Handoff edge forms** (ceo-exposure.ts:224; :178 at #229's merge): unusual handoff call forms read unexposed. This fails closed. The smoke-first `ceo rows --checks` rule is the live test of the real skill's call form.
3. **Suite-file binding** (ceo-cli.ts:139): the binding includes the suite file's sha256, so a suite-only edit refuses resume and rows. Section 6 covers it.
4. **progress.json** can undercount the remaining cells after a narrower resume. Display only.
5. **Strict-grammar setup lines** (`export PATH=...`, `set -e`, `|| true`, `$(...)`) read unexposed. This fails closed. `ceo rows` prints, per autoplan-ceo cell, how many sessions named the handoff and still read unexposed.
6. **ceo-outcome runs made before #229** can't be resumed or read. No paid ceo-outcome run exists.
7. **Capy finding 01M6P90MV7W5RDGHSQATBFVSAA** (ceo-exposure.ts:131 at #229's merge, Low). #230 closes it (section 1, change 1).
8. **`ceo rows` can't read a partial run** (#229's review note 01M6P5QQTY2GFJXHXAEZD1XVK3). rows refuses a run with no stops.json (ceo-cli.ts:194), and run.ts writes stops.json only when the run ends (run.ts:625). A run that is lost or still running has no stops.json, so rows reads nothing from it.
9. **The disagreement count.** The results post reports, as a count across all stages, how many sessions have a `findings_written` that disagrees with their host/ceo-review/ copies, read as section 4 reads them. The count is report-only and decides nothing.
10. **Multi-line `${...}` in an unquoted heredoc** (ceo-exposure.ts:177; fails open; a #230 review note the Captain accepted as a named limit). A body such as `${UNSET:+` on one line, then a Findings line and `}` on later lines, lets bash delete the Findings line while `findings_written` still reads written. If a smoke session writes this form, the smoke findings check stops the run; the count in note 9 reports it in every stage; and the next CEO amendment makes the on-disk copy primary for `findings_written`. #230's other fail-open note (`tee F # <<true`, `tee F '<<true'` and `cat > F # <<true`) reads unwritten at the build commit.

## 8. The Low from #222

Capy finding 01M6NMWPFH5N1XK3B74A6YE44F (Low) on #222 found that stage 1's FALLBACK gate needs the band to hold with every unjudged rem scored yes. So a reading whose fallback holds on judged rem but fails under that completion ended as a CEILING and printed "CEILING (34 of 48 = 0.708 > 0.60): stop", while the ladder amendment says a reading that turns on unjudged rem waits on the judges. #222 carried this to B1 as a binding item.

- The verdict kind is unchanged. FALLBACK still needs the band with every unjudged rem scored yes (line 401, the same test as #222's line 399).
- Line 405 sets the printed label to JUDGE WAIT when the kind is CEILING, the judged band, strict and unjudged-share checks hold, and only the yes completion fails.
