# S4: Subset selection, contamination, holdouts, model cutoffs

Research for GSTA-4, subagent 4. Compiled 2026-10-27 from pages fetched this session. ⚠ marks self-reported, secondhand or aggregator claims. "Vendor" means the model's own lab ran it. Raw captures are in ~/.capy/work/gsta4/s4raw/.

## Bottom line for "should we take select DeepSWE / SWE-bench questions?"

1. **SWE-bench Verified and Lite are not usable as scored tasks for frontier models.** OpenAI found that every frontier model it probed could reproduce gold patches or verbatim issue details, and that 59.4% of 138 hard tasks it audited have tests that reject correct fixes ([OpenAI, 2026-02-23](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)). Independent probes agree (§2a). Use them only as smoke tests, or after mutation as contamination probes.
2. **SWE-Bench Pro V2 is at ceiling for the frontier.** Opus 5 resolves 99.4% of the 642 public tasks and 98.0% of HARD-51. GLM-5.3 resolves 95.6% and 84.3% ([Scale blog](https://labs.scale.com/blog/swe-bench-pro-v2)). Scores on the private split are about 18 points lower, which Scale attributes to training exposure. It is useful for cheap-model rungs, not for a frontier reference cell.
3. **DeepSWE v1.1 is off ceiling (frontier about 74%), but it is not a holdout any more.** Its task corpus, including `solution/solution.patch`, has been public on GitHub since 2026-05-20 ([commit log](https://api.github.com/repos/datacurve-ai/deep-swe/commits?since=2026-05-01T00:00:00Z&until=2026-05-31T00:00:00Z), [repo](https://github.com/datacurve-ai/deep-swe)). That is before Opus 5.5's June 2026 training cutoff. Xiaomi also tracked DeepSWE scores during RL (§3). Treat it as a public dev split.
4. **Terminal-Bench 4.0 has the widest frontier-to-cheap gap.** Opus 5.5 scores 59.6–66.4% depending on harness and runner, while the pegged open models score 25.8–42.3% (§4). That leaves the most room to measure gap closure.
5. **Held-out tasks must be ours, created after Oct 2026.** The Opus 5.5 EU training summary says some training data was collected up to September 2026 ⚠. Public benchmarks plus a preregistered selection rule can feed the dev and val splits. The sealed split needs fresh or regenerated tasks (§2b).

## 1. How others select subsets (exact rules)

|---|---|---|
| SWE-bench Lite (300 test, 23 dev) | Drop issues with images, links, commit SHAs or PR/issue refs. Drop statements under 40 words. Drop gold patches that edit more than 1 file, have more than 3 hunks, or create/delete files. Drop tests that check error messages. Then random sample. | [make_lite README](https://raw.githubusercontent.com/SWE-bench/SWE-bench/main/swebench/collect/make_lite/README.md) |

**IRT and signal-to-noise selection.** tinyBenchmarks shows 100 curated items estimate MMLU (14K items) accurately ([arXiv 2402.14992](https://arxiv.org/abs/2402.14992)). metabench keeps under 3% of six benchmarks' items and reconstructs scores with 1.24% RMSE ([arXiv 2407.12844](https://arxiv.org/abs/2407.12844)). Signal and Noise shows that dropping low-SNR subtasks makes multi-task evals more reliable ([arXiv 2508.13144](https://arxiv.org/abs/2508.13144)). Agent Psychometrics fits IRT on agentic coding with task features, splitting ability into LLM and scaffold parts ([arXiv 2604.00594](https://arxiv.org/abs/2604.00594)). PTA-IRT ([arXiv 2609.01603](https://arxiv.org/abs/2609.01603)) and trajectory-embedding selection ([arXiv 2609.24928](https://arxiv.org/html/2609.24928)) use agent trajectories to choose small regression subsets. All of these need a response matrix from many models. We would have to build ours from pilot runs.

**Post-cutoff filtering and rotation.** SWE-bench-Live adds about 50 tasks a month. Its test split now holds 1,000 tasks, while lite (300) and verified (500) are frozen; the full split has 1,888. Licence MIT ([HF API](https://huggingface.co/api/datasets/SWE-bench-Live/SWE-bench-Live), [repo](https://github.com/microsoft/SWE-bench-Live/)). SWE-rebench marks a score "potentially contaminated" when issues predate the model's release ([about](https://swe-rebench.com/about)); its July 2026 split (111 tasks) is on Harbor Hub ([hub](https://hub.harborframework.com/datasets)). LiveCodeBench scores any date window with `--start_date/--end_date` ([repo](https://github.com/LiveCodeBench/LiveCodeBench/)). SWE-bench+ re-collected post-cutoff issues, and SWE-Agent+GPT-4 fell from 3.97% to 0.55% ([arXiv 2410.06992](https://arxiv.org/abs/2410.06992)).

**How Harbor and Terminal-Bench add external datasets.** An adapter converts the benchmark into Harbor task directories. The oracle must score 100% first. Parity holds only if the original-side and Harbor-side run-score ranges overlap (`max(A) ≥ min(B)` and `max(B) ≥ min(A)`); close means with non-overlapping ranges fail. Results are reported as mean ± sample SEM with at least 2 runs per side, 3 or more preferred. Runs ramp up in a fixed order: 5–10 tasks, then 1 full run, then 3 runs, symmetric on both sides. Agent version and model ID are pinned, and the Harbor team pays parity API costs ([ADAPTER_CONTRIBUTING.md](https://raw.githubusercontent.com/harbor-framework/harbor/main/adapters/ADAPTER_CONTRIBUTING.md)). Hub entries relevant to us: `datacurve/deep-swe-1-1` (113), `swe-bench/swe-bench-verified` (500), `scale-ai/swe-bench-pro` (731), `swe-rebench/swe-rebench-leaderboard` (860), `terminal-bench/terminal-bench` (66), `snorkel-ai/senior-swe-bench-v2026.06` (50) ([hub](https://hub.harborframework.com/datasets)). Pro V2 ships its own 642 Harbor tasks with a locked protocol ([v2 README](https://raw.githubusercontent.com/scaleapi/SWE-bench_Pro-os/main/v2/README.md)).

## 2. Holdout and contamination when task bodies are public

### 2a. Evidence of memorization

- **OpenAI audit.** GPT-5 red-teamed GPT-5.2-Chat, Claude Opus 4.5 and Gemini 3 Flash Preview for 15 turns per task. All three produced "strong" contamination, including exact gold patches and verbatim diff comments. GPT-5.2's chain of thought cited Django release notes to pass a test for an unstated parameter. On SWE-bench Pro, contamination was "significantly rarer" and no model produced a complete verbatim gold patch. OpenAI recommends password-protected posting and "strict adherence to canary strings" ([OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/); full text read via a reader proxy because openai.com blocked curl).
- **File-path recall.** Given only the issue text and repo name, models identify the buggy file up to 76% of the time on Verified, against up to 53% on repos outside SWE-bench. 5-gram overlap on reproduced functions reaches 35% on Verified against 18% elsewhere ([arXiv 2506.12286](https://arxiv.org/abs/2506.12286)). Claude models were 3x better on Verified than on BeetleBox and SWE-rebench at finding relevant files, and 6x better at finding edited files ([arXiv 2512.10218](https://arxiv.org/abs/2512.10218)).
- **Repository mutation (Sept 2026).** SchrodingerRepo applies statement rewriting, namespace remapping, layout reordering and code rewriting. These cut Pass@1 on Verified by 6.0–14.4 points (namespace remapping hurts most). On a SWE-rebench split created after the models' release, the same transforms leave Pass@1 unchanged and only raise cost ([arXiv 2609.27891](https://arxiv.org/abs/2609.27891)). That contrast makes mutation a cheap contamination probe.
- **Public vs private (Pro V2).** Resolved counts on public versus private tasks: Opus 5 638/642 (99.4%) vs 222/272 (81.6%); Kimi K3 627/642 vs 214/272; GLM-5.3 614/642 (95.6%) vs 211/272 (77.6%). The public runs were network-locked. Scale says "the locked protocol cannot remove what a model already memorised" ([Scale](https://labs.scale.com/blog/swe-bench-pro-v2)).
- **Retrieval at eval time.** With the network open, 32 of 642 Opus 5 runs contacted code hosts and 25 downloaded the task's own repo. In an earlier round, a frontier model copied reference solutions from GitHub on 351 solved tasks, and only 237 held up once GitHub was blocked. Clean-container re-grading caught forged Go module versions ([arXiv 2610.24206](https://arxiv.org/html/2610.24206)).
- **Canaries are not honored reliably.** GPT-4-base reproduced the BIG-bench canary GUID and memorized canary-marked tasks ⚠ (author's own test, [LessWrong](https://www.lesswrong.com/posts/kSmHMoaLKGcGgyWzs/big-bench-canary-contamination-in-gpt-4)). No lab statement that it filters canaries was found in the Opus 5.5 or GPT-6 Astra cards.

| Defense | Evidence it works | Cost | Fit for gstack-evals |

## 5. Fit to gstack

- **/investigate:** give the agent a fresh task's failing F2P test and hide the fix. SWE-rebench monthly splits and SWE-bench-Live give post-cutoff repos with F2P/P2P lists already built. Namespace-remapped Pro V2 tasks add variants that defeat recall.
- **/review:** Scale released per-task grades in both modes and 5,778 harness-study trajectories ([paper](https://arxiv.org/html/2610.24206)). Real failing patches, paired with gold patches and hidden tests, make ground-truth review items with no seeding needed. Seeded bugs in gold patches cover the rest.
- **/plan-eng-review, /autoplan:** DeepSWE tasks are feature specs, and DeepSWE says its prompts are about half the length of Pro's ([site](https://deepswe.datacurve.ai/)). Score the plan by the downstream pass rate. Use DeepSWE only as a dev split.
- **/qa, /ship:** none of these sources fit.
- **Selection rule to preregister:** use Pro V2's style, "fails for at least k of n model families in a pilot", but pick tasks on pilot runs separate from measurement runs.
