## Claimed value, one sentence

autoplan runs the CEO, design (UI plans), DX (developer-facing plans) and eng reviews over a plan in one pass, answers the routine questions itself by six stated principles, has two independent reviewers from different model families check each phase, and stops once at a single gate where the owner decides only the taste calls and the changes to their stated direction (autoplan/SKILL.md:5, 251-254, 276-308; autoplan/SKILL.md.tmpl:5-11; autoplan/DRIVER.md:5-7, 25-32).

## Two paths: what the model actually loads

autoplan has two execution paths at the pin, and they load very different text. An eval must say which one it ran.

**Path I, in-session skill (Claude Code style).** The session model reads autoplan/SKILL.md, then each phase section, then a `methodology.md` bundle that bin/gstack-autoplan-snapshot.ts builds from the sibling skill: its whole SKILL.md plus its `sections/review-sections.md` (gstack-autoplan-snapshot.ts:516-566; read in 600-line ranges, 569-575; phase sections line 3, e.g. autoplan/sections/ceo-phase.md:3). The session model does Step 0 and the review sections itself. The native reviewer subagent it dispatches never sees the sibling skill: it gets a fixed 5-question role brief plus the Implementation plan (gstack-autoplan-snapshot.ts:37-70, 656-677). The Codex outside voice gets a phase prompt written in the phase section (e.g. ceo-phase.md:82-95).

**Path R, runner-driven (any parent, including Capy).** The parent reads autoplan/DRIVER.md, never SKILL.md (DRIVER.md:5-7, 45-46; docs/unattended.md:402-409), and loops `gstack-autoplan next/submit/answer`. The parent never reads sibling methodology. The runner still prepares methodology.md for each opened phase and records its path (lib/autoplan-run.ts:166, 188), but no prompt includes it or names its path (lib/autoplan-prompts.ts:188-205). An in-session run that sees `SESSION_KIND: unattended` is sent to this path too (autoplan/sections/unattended.md:5-11; SKILL.md:271, 668-669).

### What a Capy-driven unattended run loads from each sibling skill (Path R)

Mode selection: the runner's session kind is `GSTACK_SESSION_KIND` or else `unattended` (lib/autoplan-run.ts:115). With `GSTACK_CAPY=1`, session kind unattended and no `--kind`, `--full` or `--ceo-only`, the run is the lean `feature` kind (lib/autoplan-lean.ts:41-45). Section mode is `light` whenever session kind is unattended or `--light` is set, else `full` (lib/autoplan-run.ts:179). In `light` mode `sectionLoadFor` puts the sibling's `runner_only` checklist file into the native prompt and records every other section id as "loaded" or "skipped" (lib/autoplan-prompts.ts:166-178). "Loaded" is only a recorded id: `writePrompts` inserts only `sections.checklist` and `sections.line` (lib/autoplan-prompts.ts:197, 203). Every sibling manifest at the pin lists exactly two sections: `review-sections` (scope `always`) and `checklist` (`runner_only`) (plan-*-review/sections/manifest.json). `sectionScopeOff` can only turn off `ui` or `dx` scoped sections (lib/autoplan-prompts.ts:160-165), so the scope filter skips nothing at the pin and prints `Skipped sections: none`.

**Default Capy run (lean, `--kind feature`).** Phase order is `eng` alone (lib/autoplan-run.ts:117); CEO, Design and DX are marked skipped as merged into the one eng reviewer (lib/autoplan-run.ts:124; lib/autoplan-lean.ts:28). No outside voice (lib/autoplan-run.ts:120, 128, 192), one round (lib/autoplan-run.ts:130), no carry (lib/autoplan-run.ts:136). The single native prompt is, in order (lib/autoplan-prompts.ts:203):

So the sibling skills reach the model as four checklist files at most. Nothing from any sibling SKILL.md or review-sections.md reaches the reviewer or the parent.

**Capy run with `--full`.** Phase order is ceo, then design if UI and not docs-only, then dx if DX and not docs-only, then eng (lib/autoplan-prompts.ts:100-102). Each phase's native prompt is that phase's 5-item role brief plus the plan plus that phase's sibling checklist (light mode, lib/autoplan-run.ts:179). The outside prompt is the boundary line, OUTSIDE_ROLE for the phase and the plan, with no checklist (lib/autoplan-prompts.ts:204). Every later phase's prompts (both voices) carry each closed earlier phase's consensus (lib/autoplan-run.ts:168-178). Max rounds default 2 (lib/autoplan-run.ts:130; lib/autoplan-budget.ts:23 by grep).

**Docs-only plan** (flag, marker, or every Implementation-plan path docs-class; lib/autoplan-prompts.ts:68-72): design and DX are dropped (lib/autoplan-prompts.ts:101), CEO runs native only (lib/autoplan-run.ts:193), Eng keeps both voices (lean still has no outside voice).

**`--ceo-only`**: phase order `ceo` only (lib/autoplan-run.ts:117); native prompt = CEO brief + plan + CEO checklist; ends `status=reviewed`, no gate (bin/gstack-autoplan:77; docs/unattended.md:763-785).

**`--kind fix`**: no review, writes nothing (bin/gstack-autoplan:461-469; lib/autoplan-lean.ts:30-34).

**`full` section mode** (session kind not unattended and no `--light`, reachable only by setting `GSTACK_SESSION_KIND` to another kind): no checklist at all; the native reviewer sees only the 5-item brief and the plan (lib/autoplan-prompts.ts:175).

## Steps vs intention

1. **The Capy path loads almost none of the review methodology it claims to run.** SKILL.md promises every section at full interactive depth (SKILL.md:253, 361-362). In a Capy run (Path R) the only sibling text any model sees is each phase's checklist of about 30 lines (lib/autoplan-prompts.ts:175, 197, 203; lib/autoplan-lean.ts:121-125). The runner prepares methodology.md (lib/autoplan-run.ts:166) but never puts it or its path in a prompt; the checklist header says the methodology file holds the full sections (lib/autoplan-prompts.ts:197) and gives no path. The checklists then ask for outputs a reviewer subagent cannot produce: review log row, next-skill handoff, saved terminal report, chaining (plan-ceo-review/sections/checklist.md:15, 33-36; plan-eng-review/sections/checklist.md:34-36). A run can pass every runner check (INPUT receipt, findings fence, DRAFT line) while AP-X-2, the depth of AP-CEO-1 and the artifacts of AP-ENG-1 (diagram, test plan file) are absent.
2. **The light-mode scope filter is a no-op at the pin.** `--light` claims to load each phase's checklist plus the sections its scope needs (bin/gstack-autoplan:80), but every sibling manifest has only `review-sections` at scope `always` and `sectionScopeOff` acts only on `ui` and `dx` (lib/autoplan-prompts.ts:160-165). Loaded sections are recorded ids that never enter a prompt (lib/autoplan-prompts.ts:176, 203). `Skipped sections: none` reads as full coverage and is not.
3. **The Capy default drops dual voices, a main intention.** With no kind on Capy there is no outside voice, one round and one reviewer (lib/autoplan-lean.ts:41-45; lib/autoplan-run.ts:117, 120, 192). AP-X-3 cannot be met; consensus is N/A by design. User Challenges are defined as both models agreeing (SKILL.md:304-308), but in lean a single reviewer can flag `user_challenge: true` (lib/autoplan-prompts.ts:126). How the gate treats a single-voice challenge in lean was not read (lib/autoplan-gate.ts unread).
4. **The independent native voice is a 5-question generic brief.** In both paths the native reviewer gets NATIVE_REVIEWS (gstack-autoplan-snapshot.ts:37-70), not the sibling methodology. In Path I the session model does the methodology itself and then fills the consensus table from two short reviews. The table can be filled with N/A cells and the phase still closes (ceo-phase.md:165-167).
5. **Completion checks are presence checks the model rates itself.** Pre-Gate Verification lists headings and tables (SKILL.md:596-605); after two repair attempts the run warns and goes on (609-610). The author notes that headings are not completion (SKILL.md:340) and that retention checks prove bytes, not correctness (phase-close.md:37-40; gstack-autoplan-snapshot.ts:333-335, 733-734). PLAN_REALITY blocks only in an in-session unattended run (SKILL.md:612-614); the runner records it as report only (lib/autoplan-run.ts:305-316).
6. **The principles push toward bigger plans with little brake.** P1, P2, P6, never reducing scope in Eng (eng-phase.md:6) and the mechanical rule against reducing scope on a complete plan (SKILL.md:297) let expansions under 5 files auto-approve (SKILL.md:279). Only 3-5 file borderline cases reach the owner (SKILL.md:301). A run can follow every rule and hand the owner a larger plan they never chose.
7. **Gate defaults differ by path.** Path I recommends approve as-is for the plan item (SKILL.md:628); Path R tells the parent to offer `rec`, every recommendation with plan changes, as the default (DRIVER.md:32). The same review can end with or without its accepted fixes depending on the host.
8. **The publication guard checks order and a message, not substance.** The hook verifies close-packet reads and that a `Phase N complete.` report came before the next phase (autoplan/bin/phase-publication-hook.ts:445-485, 568-627). On Capy it is not installed; the runner writes a GUARD_NOT_INSTALLED deviation at init (lib/autoplan-run.ts:131). The section manifest says no paid eval checks section reads since the chain eval was retired (autoplan/sections/manifest.json:5).
9. **Outputs reward volume.** One audit-trail row per auto-decision (SKILL.md:584), under 3 sentences treated as compression (SKILL.md:377-378), and prose for each of Sections 1-11 (ceo-phase.md:170-173). Counting rows proves nothing about decision quality.
10. **CEO mode is fixed.** SELECTIVE EXPANSION is forced (ceo-phase.md:10) and the review log hardcodes it (SKILL.md:698), while the sibling's 0E picks a mode by plan type; only `--ceo-only` honors 0E (sections/ceo-only.md:20-23).
11. **Order inside the Design and DX phases is ambiguous.** The sections bind the snapshot and dispatch voices first and list Step 0 afterwards (design-phase.md:12-33 vs 109; dx-phase.md:16-37 vs 113-116); SKILL.md spells out preliminary work only for CEO (SKILL.md:322-323).
12. **A gstack-only CEO rule applies to every plan.** Listing each part the plan adds to gstack (ceo-phase.md:14-15) is met by "none" on a non-gstack plan.
