## Steps vs intention

1. **A clean status is reachable only by finding nothing.** STATUS is "clean" only when `issues_found=0`, `unresolved=0` and `critical_gaps=0`, and resolved findings still count (RS:1376). The dashboard clears Eng Review only on a clean record (RS:1435-1437), and the report appends "eng review required" otherwise (RS:1323-1324). So a thorough review that finds and fixes ten issues shows ISSUES OPEN and NOT CLEARED, while a shallow review that finds none shows CLEARED. The text says "issues_open can mean mapped work, not failure" (RS:1376), but the verdict logic does not follow that. The gate rewards a low finding count, which works against ENG-1 to ENG-5.
2. **Test coverage is planned, not built or measured.** The review must not build tests (RS:619, RS:647), the star ratings are the reviewer's own (RS:706-709), and the real X/Y coverage numbers are left to /ship (RS:725). A run can produce a perfect diagram with value cards for every gap while the build ships none of them. ENG-2 is met only in BUILD, which this skill never checks.
3. **Reality rows check form, not truth.** `gstack-plan-reality check` confirms that a row line exists, carries a receipt token, and that the cited file exists and the line number is within it (lib/plan-reality.ts:260-293; lib/plan-reality-receipts.ts:9-13,50-78). It never checks that the line supports the claim, so `REALITY: already-done pass README.md:1` passes. In interactive runs a miss only means "repair twice, then warn at the gate" (RS:426; lib/plan-reality.ts:19-20), so nothing blocks. ENG-5's "met" needs a judge that reads the receipts.
4. **Confidence is self-rated and the quote is not checked.** The pre-emit gate says to quote the motivating line or force confidence to 4-5 (RS:147-158), but no tool verifies the quote, and the model picks its own score, which decides what is shown or suppressed (RS:131-137).
5. **The exit gate checks layout only.** The blocking gate verifies that the last heading is `## GSTACK REVIEW REPORT`, the table has six columns, the last line is the unbolded sentinel, and the log helpers ran (SKILL.md:521-530). An empty or shallow review with the right layout passes. The Section self-check (SKILL.md:505-509) asks the model to confirm it did the work, which is self-attestation.
6. **"Never condense or skip a section" rewards volume.** All four sections must run in full even for strategy or infra plans (RS:510-511), and outputs are "always" (CHK:20-36). For a small plan this pushes toward filler. Performance can be met by marking every scale "unknown" (RS:864-865).
7. **The failure-mode critical gap is a three-way AND.** Only a failure with no test AND no handling AND silent is critical (RS:1186). A failure with a planned test but no handling, or with handling that silently swallows the error, is not flagged, though ENG-3 plainly wants silent failures caught.
8. **Effort numbers come from default ratios.** Task effort uses fixed human-to-CC ratios (scaffolding about 100x, tests about 50x and so on, RS:1232), and briefs must show both scales (SKILL.md:176). The `numbers` reality row wants every number re-derived and tagged measured or estimated (lib/plan-reality.ts:66-69), but the checker reads only REALITY lines, so the unbased estimates in tasks and briefs are never checked.
9. **"Boil the ocean" against "smallest change".** The completeness check says full tests, edges and errors cost 10-100x less with AI, prefer completeness, "Boil the ocean" (RS:415-416), while the preferences say smallest clear change, no premature abstraction, and no test without a regression it would catch (SKILL.md:278-282; RS:711-716). The preamble reconciles them as "complete coverage, minimal code" (plan-eng-review/sections/preamble.md:206@b493d4e31), but a run can satisfy one by violating the other.
10. **The user-decides intention is replaced when no human is present.** Spawned and unattended runs auto-pick the recommended option (SKILL.md:113), so ENG-6 becomes "the reviewer decides and records it." The ledger and read-back steps still run, so the record looks the same as an interactive one.
11. **Decision bookkeeping can crowd out substance.** Each choice needs a comparison grid, a saved pending record, a full Read-back, one question, a saved answer and another Read-back (RS:258-376). This is well aimed at bundled or misrecorded approvals, but the number of writes per finding gives an incentive to raise fewer findings.
12. **Complexity gate counts are self-reported.** The 8-file and 2-class thresholds use the reviewer's own counts, with "label estimates" (RS:395-399, RS:430-432). Just under the threshold, the gate and its structure question are skipped.
13. **The outside voice's "clean" was soft at b493d4e31.** At this revision lib/outside-review-result.ts accepted a prose no-findings sentence as clean; the fix at the pin (#4140) says every earlier prose form "leaked a false clean". An outside-voice clean recorded at b493d4e31 is weak evidence (see Notes).

**What an eval designer must know.**
- This skill writes no code by design (SKILL.md:24). ENG-1, ENG-2, ENG-3, ENG-4 and ENG-7 are strongest in BUILD and AFTER, so an eval that scores only the review record measures plan text, not the product. To test the claim, pair the review with a later implementation step (same model, same task) and score the diff, its tests (for example by reverting the guarded behavior) and seeded post-launch failures.
- Under autoplan on Capy defaults (`--kind feature`), the eng phase runs as one merged reviewer and may never run the Decision procedure, the reality rows or the outside voice. Freeze the autoplan kind in any prereg and report exposure: which markers from the table above actually appear.
