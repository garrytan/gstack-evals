# Wiring: open items

The binding in wire.ts, wire/real.ts and wire/host.ts connects the real providers to the lane's paid rows. Real providers exist only inside the ledger service's process on the controller host, and only after a row's start rules and ledger admission pass. Off that host every factory refuses with E_DCW_OFF_HOST. Nothing is built at import time, and keys are read by name when a provider is built.

The items below are choices the binding could not make without moving a scored outcome or the money, or pieces that are still unbuilt. Each needs the Captain's ruling or a later unit before the first paid launch.

## The wiring file

A host run reads one wiring file (wire/real.ts readWiring). A missing choice refuses with E_USAGE naming it.

1. **Retry budget.** The proxies' retry budget (paid item 1) is the file's `retry`. The Captain ruled it at 3 attempts within 15 minutes (wire/real.ts RULED_RETRY); a file that names another budget refuses with E_USAGE.
2. **Drift scan interval.** How often a session proxy's journal is read for drift (paid item 5) is the file's `scanMs`.
3. **Sessions section.** The gstack pin sources and the expected image digest come from the file's `sessions` section.
4. **VM section.** Ubicloud's project, location, VM size and image, the private subnet, the SSH key, the browser path, the price per hour, the VM proxy endpoint and the mirrors come from the file's `vm` section.

## Money

5. **J1 reconcile returns null.** The ledger provider's reconcile always returns null, so an unknown charge stays held until the owner's reconcile, as PD-18 rules. The sessions row prints a "held" line for it. The session-level reconcile is exact when the session proxy holds the attempt's meter, and `judged` is always false within one launch.
6. **Proxy folders and recovery.** Proxy journals sit under the service's journalDir in `direct/` and `sessions/`. Every slot a proxy binds is linked to its sub-reservation in `links/<folder>.ndjson` before anything is sent (money/journals.ts). On a same-host relaunch, recovery reads every journal with main's reconcileJournal and settles each held sub-reservation whose linked meters all show an outcome, at their spend. A sub-reservation with no link, a journal that could not be read, or a call with no outcome stays unknown under PD-18, and the scan is written to the state folder as `journals-<time>.json`. A relaunch on a new host has no journals to read, so everything in flight stays unknown.
7. **Terms digest.** A reply's termsDigest is the sha256 of the pinned routing terms, matching paid/pin.ts termsRecordsOf. It is not a fresh endpoints read per call. No row writes the `--terms` file from the pin record yet.

## Sessions

8. **Containment retry.** When a container fails C2 or C3, the binding prepares a fresh session folder from the same export instead of exporting again. One combined containPoint runs: after-install for the gstack arms, before-session otherwise. A second failure throws E_DCW_CONTAINMENT and stops the launch, leaving the admitted round in flight for the Captain.
9. **errorSeen.** The shared driver reports a non-success result after model output as harness_crash. run/stream.ts reads the session's stream: when the last top-level message before that result is Claude Code's rejection of the model's tool call (a tool_use_error naming an input validation failure or a tool that does not exist), the termination is malformed_tool_call. errorSeen comes from the attempt's session proxy journal (paid/sessions.ts errorSeen): a refusal, or an outcome that was an upstream error status, never sent or unknown, for the attempt's meter. A journal that cannot be read counts as an error seen. PD-17 then splits as run/session.ts endOf rules: errorSeen true is outside the agent (J1 retry, then infra-missing), false is an arm stop scored after its one fresh retry.
10. **backgroundWaitMs.** Resolved (PD-32): every arm's review session sets the driver's wait to frozen.ts BACKGROUND_WAIT, 3,600,000 ms, through run/arms.ts sessionSetup. See item 22.
10a. **The install network and the install digest.** The Captain's ruling 1F: the gstack arms' container joins the bridge install network only for `./setup`, before the session starts. After it leaves, run/docker.ts verifyInstall reads the container's networks and stops the session with E_DCW_INSTALL_NETWORK unless the trial network is the only one. It then reads every file of the pinned tree inside the container and stops the session with E_DCW_INSTALL_DIGEST when their digest differs from the pinned tree's, read on the host from the verified tree. Files `./setup` adds are not counted. Each session's digests and networks are written to its `install.json`.
11. **Evidence for the reference arm.** The sessions row now reads evidence files only for the full-information reference cell. Before this fix every other arm crashed with E_USAGE, because armPrompt refuses evidence for them.
12. **The exports layout.** Each unit's export folder holds `repo/` (with its evidence files), `plan.md`, `context/` and `c2.json`. No row writes `c2.json` or `stage3.json` yet.

## Controller host

13. **Provisioning.** The controller host provisions no Docker, no trial image and no gstack pin sources (money/controller-host.ts controllerProvision).
14. **Launch.** Built: `gstack-evals dc host launch` (wire/host.ts) creates the WAL host and the controller host, unpacks the plan's work folder into the host's tmpfs work folder and runs the plan's stage as row 1 through money/host-main.ts and runOnHost. `dc host next` sends each later row, with its own inputs, to the same ledger service once the last row has ended, and `dc host status` prints each row and, for rows whose lines carry no unit text, the last lines of its log. The teardown seals the work folder on the host before anything is copied back (PD-41). tests/dc/wire/launch.test.ts and wire/dryrun-launch.ts's W-launch case drive the whole path keyless.
14a. **The host's checkout.** Built: the launcher ships the commit as a git bundle with no history (money/controller-host.ts repoBundle), and the host checks it out at /var/lib/dc/repo as a git repository marked shallow at the commit (repoCheckout). A launch and a recovery then check that HEAD is the commit, its tree is the commit's tree and no tracked file changed, and refuse with E_DCH_CHECKOUT otherwise; a relaunch, which ships nothing, checks the same before it starts the service. Before this fix the host unpacked a git archive with no .git, so the host's own dry run failed W-host-row at git rev-parse HEAD:src/adapters and start rule 5 refused every row. tests/dc/wire/host-checkout.test.ts runs the real keyless dry run from a checkout built this way, and shows that a bare archive fails it.
14b. **The work folder's tmpfs use.** Built: each row's log ends with the work tmpfs's use, its size and the row's peak, sampled on the service's tick (money/host-main.ts); rows.json and stage.json record them, and dc host status prints them for each row. dc host next refuses with E_DCH_TMPFS_HIGH when the last row's peak or the use now is above 80% of the tmpfs (money/controller-host.ts TMPFS_GUARD_SHARE).
14c. **The approval record at teardown.** Built: the teardown copies the host's record beside the Captain's record, on its file system, moves the old record aside only then, renames the copy into place, and puts the old record back if a step fails (wire/host.ts writeArchive). Before this fix the host's record was renamed from the archive on /dev/shm onto a record on disk, which failed with EXDEV after the old record had moved aside.
14d. **Docker in the sandbox VMs.** Built: the sandbox VMs boot the plain ubuntu-noble image, which has no Docker, so the preamble's dockerhub step now only writes /etc/docker/daemon.json and restarts nothing (stage3/sandbox.ts mirrorConfig). In a VM whose spec names the dockerhub mirror, the controller's install puts docker.io on from the apt mirror after the preamble (stage3/install.ts DOCKER_APT), enables and starts it, and fails unless docker info lists the mirror. It runs between the install's markers, so Docker's installed files go on the controller's list like the browser's, and what Docker writes later stays in the audit's view. A failed preamble or install step keeps its exit code and its stderr, cut to 400 characters with each word that holds a key pattern or drive path replaced (stepStderr), and an audit that fails after one ends its reasons with it, so the E_DC_SANDBOX_AUDIT stop names the step. Before this fix systemctl restart docker failed on every VM, the preamble stopped before the egress filter, and the stop said only that the ruleset command exited 1. Docker's own iptables rules sit in its ip and ip6 filter and nat tables, and parseRuleset reads only the inet dc out chain. tests/dc/stage3/sandbox.test.ts and tests/dc/recipes/recipes.test.ts test both.
14e. **The teardown's copy of the sealed archive.** Built: the teardown streams the sealed archive, the off-host lines and the snapshot into the archive folder over SSH (stage3/ubicloud-real.ts sshStreamer, UbicloudBackend readTo), never holding them in memory or decoding them as text. Before it deletes a VM it checks the archive's age header on the host and in the copy, and the copy's size and sha256 against sha256sum on the host. A mismatch deletes the copy, keeps both VMs and refuses with E_DCH_SEAL (money/controller-host.ts teardown). A teardown run again finds the archive sealed and the work folder empty, so it copies the archive again and goes on. Before this fix the teardown read the 3.4 GB archive with one cat whose output the SSH runner held as bytes and as text, and the launcher died at its memory limit. Uploads stream the same way where they can: the trial image tar goes to the host from its file (wire/host.ts, the image's tar as a file source), and every sandbox gets the browser build piped from tar and the Node tarball from its file (stage3/install.ts, UbicloudBackend write with a file source). The launch's work tar, a row's inputs and the repo bundle are still built in memory from tmpfs (money/controller-host.ts upload, wire/host.ts tarOf). tests/dc/money/controller-host.test.ts tests the copy with a runner that refuses any held output over 256 KiB, and tests/dc/stage3/ssh.test.ts streams through a local sshd.
14f. **What a sandbox VM needs before a recipe or a qualification runs.** Built: the preamble makes /work for the run user, since the session and qualification jobs write /work/app.tar first (stage3/sandbox.ts preamble), and the fake's write now fails into a folder nothing made. Every sandbox gets Node 24.22.3, the latest Node 24 LTS patch, pinned with its tarball's sha256 in stage3/node-pin.json (stage3/install.ts NODE). The wiring's vm.nodeTarball names the tarball in the work folder; the launch and the VM provider check its sha256 against the pin (wire/real.ts nodeTarball), and the install unpacks it to /opt/dc-node, links node, npm, npx and corepack into /usr/local/bin and runs corepack enable there (stage3/install.ts nodeFiles). The preamble's npm step also writes COREPACK_NPM_REGISTRY to /etc/environment, so pnpm and yarn resolve through the npm mirror. Node's files go on the controller's list like the browser's. After its apt fetch the install fails unless the kernel log holds at least one DCNET line, so an egress log that logs nothing can't pass the audit with zero egress; the audit itself is unchanged. Every apt-get on the controller host, its mirrors and the sandboxes waits up to 600 seconds for the dpkg lock. A host plan with mirrors off refuses when the wiring names the controller's mirrors (wire/host.ts hostRules). A ledger service running as root runs its review containers as the host's run user and gives each session folder to that user (run/docker.ts containerUser, sessionFolder); C3 is unchanged and still refuses root.
14g. **Node-version drops in stage 0.** Built: the recipes row prints each candidate's declared Node (engines.node, .nvmrc, .node-version), whether pinned Node fits it and whether the failing step's stderr was an engine mismatch, by label only, and never the stderr (recipes/node.ts, recipes/sessions.ts). It writes node-drops.json to its sink. When 3 or more candidates that did not qualify declare a range pinned Node misses or failed on an engine mismatch, the gate check and authoring rows refuse with E_DCW_NODE_DROPS naming the labels (wire/recipes.ts nodeDropRule, wire/author.ts, both read --screen). The Captain clears it by writing node-cleared.json into the recipes sink with exactly those labels. How a recipe qualifies or drops is unchanged.
14h. **Stage 3's build trees.** Open: stage3/build.ts still sends each build's tree from memory. It stays out of this fix because stage 3 refuses until its pieces are ruled (items 19 to 21).
14i. **The launcher's in-memory tars.** Guarded: the launcher still packs the work folder at launch and a row's inputs at next as a tar in memory, held twice during the upload, so it now refuses a folder over 2 GiB before packing it, with its size named (wire/host.ts tarOf). The work folder at launch is about 0.65 GiB once the clones run on the host. Large inputs go to the host as a row of their own.
14j. **The Node pin's path.** Built: the launch's VM file check and the host's VM provider read the Node pin at lanes/design-constructed/stage3/node-pin.json under the repo root (wire/real.ts nodePinPath), the file stage3/install.ts reads as NODE. The fakes had kept it at <root>/stage3/, so the first launch at the real layout refused before any VM. tests/dc/wire/node-pin.test.ts reads the real tree.
14k. **The egress filter as one transaction.** Built: the preamble writes the whole inet dc table in one nft -f step from a here-document: the table, the output chain with policy drop, the loopback and established accepts, each allowed endpoint's logged accept, then the logged drop (stage3/sandbox.ts egressFilter). nft applies it whole, so the drop policy never stands without the established accept. Before this fix each rule was its own SSH exec, and the chain step's drop policy came before the established accept, so the VM dropped its own SSH replies: stage 0's first recipe VM stopped with E_DC_SANDBOX_AUDIT after the chain step exited 255, and the audit's SSH failed too. The fake now keeps each VM's chain as its nft commands write it, reading a transaction whole and a split order step by step. Once a drop-policy output chain has no established accept, that exec and every later one exit 255 with no output, and the audit lists the chain the VM holds. tests/dc/stage3/sandbox.test.ts shows the old order failing at the chain step and the transaction passing. The other preamble steps, their order and the listing parseRuleset reads are unchanged.
14l. **The preflight row.** Built: gstack-evals dc preflight --out <new sink> runs on the host through dc host next, after the model probe and before the clones row (wire/preflight.ts). It builds the VM provider the recipes row uses, with the same wiring, mirrors and sizes, admits dc-hosts and runs one offline qualification VM through sandboxed(): the full preamble, the controller's install (the browser, Node, Docker and the egress self-check), then a job that touches the session marker, reads the kernel log's DCNET count, copies the fixture app in wire/preflight/app in as qualification copies a candidate, and runs qualification's own steps on wire/preflight/recipe.json (recipes/qualify.ts setupSteps, unchanged): a pinned Redis image pulled through the dockerhub mirror and started with docker run, pnpm 9.15.9 through corepack and one pinned dependency from the npm mirror, the build, the start and the serve wait. It loads the root once in the pinned Chromium through the browser seam and requires HTTP 200; the fixture answers 200 only when Redis answers PING. The audit must pass and must show at least one accepted connection to a mirror endpoint. It prints one line per step, the audit's ok or kind with its reasons, the egress and blocked counts and the VM's measured minutes, never key or unit text, and exits with E_DCW_PREFLIGHT on any failure. No model is called and nothing is scored. Its providers see only UBICLOUD_API_KEY and UBI_OWNER (wire/host.ts ROW_KEYS), and its VM settles on dc-hosts like any sandbox. dc host launch, next and relaunch refuse the clones row and every later row unless the host's latest preflight row ended done (wire/host.ts preflightRule); the model probe, the preflight and the items listing may run before it. The keyless launch runs it as row 2 on a simulated Ubicloud with a scripted browser (wire/dryrun-launch.ts, through RealSeams.vm), and tests/dc/wire/preflight.test.ts covers a pass and a page other than 200, an audit with no accepted connection and a failed install step.

## VM world and stage 3

15. **In-VM agents.** The VM provider binds the recipe agent (PD-31): wire/real.ts realVm builds stage3/agent.ts runVmAgent through vmSessionAgents, so the recipes row runs Claude Code from the pinned tarball in each recipe VM over SSH. Its model calls reach dc-base-apps' metering proxy through the VM proxy endpoint on a slot bound to the admitted sub-reservation, and the slot's bearer sits only in an env file under /run that the controller removes. The controller installs Claude Code only in a VM that reaches the proxy. Stage 3's pieces (the build agent, the build reader, stage 3 authoring and the DES-4 judges) are their own provider (wire.ts Stage3Provider). On the controller host it refuses with E_DCW_NO_PROVIDER before it reads a key or makes a VM, and the stage3 row builds it before the VM provider. runVmAgent already takes a build's env, but no build agent is bound until the Captain's go to start stage 3. tests/dc/wire/real.test.ts tests both ways, and wire/dryrun-cases.ts's PD-31 case fails if stage 3's pieces stop refusing.
16. **Stage 3's Opus block.** The stage3 row renders each candidate's Opus block with score/parse.ts renderList, from pass 1 and else pass 2, as frozen. Start rule 7 requires a stage 2 Opus pass 1 row for each candidate. The row settles the three stage 3 items at its end.

## Phase 1b open items

Each piece below was a choice the binding could not make without moving a scored outcome or the money. Each item names the PD row that rules it and says whether it is built. Items 19 to 21 need text or a format that neither the preregistration nor frozen.ts fixes, and each could move a stage 3 read; PD-31 keeps them open for stage 3, none is built, and each refuses until the Captain's go.

Until that go it refuses with E_DCW_NO_PROVIDER (wire/real.ts, the stage3 factory). Not built: it stays open for stage 3.
20. **Stage 3 authoring.** Not frozen: Opus's prompt for the fixtures, key checks and scenarios, the JSON shape of a key check body and a scenario body (stage3/seams.ts keeps both opaque), Sol's audit prompt and its verdict format, and each call's output cap. Not frozen: the prompt text, how the two desktop and phone pairs are sent and in what order inside a pair, the reply format, and which reply is unparsable and so retried once before the read is missing. PD-31 rules it: written before stage 3 starts as a pre-data deviation, read once on GPT-6 Astra as a read-only correctness review, and sent to the Captain with the request to start stage 3. Until that go it refuses with E_DCW_NO_PROVIDER (wire/real.ts, the stage3 factory). Not built: it stays open for stage 3.
22. **backgroundWaitMs.** Built (PD-32): the driver's wait for background work at a turn's result is 3,600,000 ms in every arm (frozen.ts BACKGROUND_WAIT, set by run/arms.ts sessionSetup and passed by wire/real.ts). Each session's own limits still bind: its 90-minute timeout runs on, and a timeout while it sits idle on held work ends it as the driver's E_BACKGROUND_DEADLINE, read outside the agent. The sessions row prints, per arm and model, how many sessions background work held at their first result (the driver's session_end shows they sat idle), how many ended at the wait's deadline and how many ended another way with work still out (run/session.ts printBackgroundAtResult). run/dryrun-cases.ts's PD-32 case tests it.
23. **errorSeen's window.** Built as it stood (PD-33): errorSeen reads every error in the attempt's journal, as ruled ("inside the attempt"), so an upstream error the proxy retried and recovered from early in a session still makes a later malformed tool call outside the agent. The Captain kept this reading. The comments in wire.ts SessionDrive and run/session.ts endOf now say "inside the attempt".
24. **The rejected-call marker.** Built, with no PD row of its own: PD-17 rules how a malformed tool call reads, and run/stream.ts matches Claude Code's tool_use_error text for an input validation failure or an unknown tool. It is checked against hand-written stream lines only, not a real CLI session at the pinned Claude Code version, so that check stays open.
25. **The model probe's ledger item.** Built (PD-34): the modelprobe row (wire/modelprobe.ts) runs paid/pin.ts modelProbePlan through runModelProbe, one short call per model (16 output tokens), first after the go. It runs on the controller host only, under the same start rules and ledger admission as the other paid rows, and off the host it refuses with E_DCW_OFF_HOST. Every probe call charges dc-gate-check, and the row leaves that item's one lease open for the gate check. A reply that names no provider resolves through OpenRouter's generation record; one that still names none, or names another provider, stops that model as a drift (PD-9). The row prints each probe line and each problem, and any problem refuses with E_DCW_MODEL_PROBE. paid/dryrun-cases.ts's PD-34 cases test it.
26. **Start rule 9's provider compare.** Built (PD-20): read/start.ts startRule9 compares with money/served.ts foldProvider (PD-20) and prints both raw names when only the spelling differs.
27. **The gate check's fix step (PD-21, PD-35).** Built as the Captain ruled. A planted drop item marked fix gets one fix call from its author. The fixed unit then goes through step 3's screen again, and a unit that fails it is a miss with no second audit. Otherwise both auditors audit the fixed unit. A drop verdict on the item in the second audit counts as caught (an auditor drops it), and a second fix verdict counts as a miss, although PD-2 would drop the item from a production key. Kept by the second audit, the item counts as caught only when its text changed and it passes its case's keyless defect check (author/gatecheck.ts DEFECT_CHECKS). B2's check passes when one of the item's pointers lands on an evidence file line holding a word of the detail's needle (K7's needle: the detail's words minus the 40 stop words). B6's check passes when the item names at least one component outside a file path, and each one it names stands as a whole word in a base-app file it cites. A named component is a PascalCase name of two or more humps that names a code file in the base app, or any PascalCase name a cited file declares. A fix that changes the text but leaves the defect is a miss, and E_DC_GATE_CHECK fires. The result's detail prints the item's statement and detail before and after the fix, and notes when the check already passes the item as planted, since it then reads nothing.
28. **Applying the re-priced caps (PD-30).** Built: the reprice row (wire/reprice.ts) runs before stage 2. Start rule 7 holds it until --stage1 records every stage 1 pass (a tier admitted, the twins tracking, the Opus judge check, the smoke rules and the admission read) and until the re-priced projection is within $5,000. For each item read/admission.ts projectionRerun re-prices, it records the new cap as a raise in main's approval record, the quote being the rerun's deviation line word for word, and writes repriced.json to its sink. Only items whose measured need passes their cap are re-priced; caps are never lowered, and a recorded re-pricing at or above a new need is kept. An item already admitted refuses. Each launch's ledger check (wire/start.ts admitItems) admits a recorded cap that is the frozen cap, or a raise above it whose quote is that item's deviation line, and sets the controller's cap to it; any other recorded cap, a hand raise included, refuses. wire/dryrun-cases.ts's PD-30 cases test it. The stage 2 sessions row checks the same start rule 7 (wire/reprice.ts stage2Rule7): before any key read or admission it refuses unless its --stage1 records every stage 1 pass and its --reprice folder holds the reprice row's repriced.json. No row writes --stage1: the run thread writes it from the rows that read stage 1's passes.
29. **What counts as a session a drift stop cut (PD-25).** Built as it stood (PD-36): wire/sessions.ts reads an attempt as a drift stop when it ended other than completed and a provider drift stop covers its model and arm when it ends. A session that completed before the stop is read as completed.
