# Outcome-skills session driver

`gstack-evals outcome serve` runs one G admission batch on the program's envelope host: one U4 lease per stage at its line item's cap, one metering-proxy slot per session, and a control plane on 127.0.0.1 that real_agent opens and closes sessions on. The leases, their closes and every cap stop live in O6's record.

A PF stage (pstack-checks, `--stage <pf item>=pf:<arm>,...`) serves the PF arms on its item's models and opens two slots per session, a task turn and a wrap-up turn, each named by meta.phase and held to that phase's allowance and wall limit. A task open needs room for both allowances; lanes/outcome-skills/pfchecks/README.md "Driver" lists the rules.

## Operator rule: a driver failure ends the item

If the driver fails with E_INTERNAL or E_LEASE_UNSETTLED, each line item it was serving ends incomplete, and the driver is not launched again for that item unless the Captain reads the ledger and rules otherwise.

## Cap stops

When a stage runs out of room, the driver drains it as cap_stop, then writes the stop into O6's record (`items/<item>/stop-<slot>.json`) before it answers the 409 CAP_STOP. A none stop drains every stage and writes a stop on each stage's item. From then on O6 admits no new lease on a stopped item, and a relaunch for it is refused with CAP_STOP.

If the stop can't be written, for example because the item's directory in the record is read-only, the driver appends a `stop` line for each stopped stage to the run directory's sessions.jsonl, answers 500 E_INTERNAL, stops every stage and exits 2. The stage was drained as cap_stop first, so every close of its lease still carries the stop as `cap_stop`:

- the driver's own settle, when the record is writable again by then;
- a later `gstack-evals ledger settle --lease`, because the driver keeps the stop in its local ledger before it writes the stop record, and the local ledger puts it in every close it stages for the lease;
- a relaunch's recovery, which reads the `stop` line.

If the driver is killed after its local ledger keeps the stop and before the stop record is written, a relaunch reads the stop from the local ledger, after O6's record and before sessions.jsonl. A none stop found there refuses the whole launch with CAP_STOP, whatever stages it names, a told stage the killed launch never served included. A told stop refuses its own stage. When the stop sits on a lease O6's record already shows closed, the relaunch first writes it into the record as that lease's stop, so O6 then refuses a new lease on the item from any ledger.

A told stage counts as finished only when it ended completed or cap_stop. After a told cap stop, none drains and settles as completed only once every told stage has finished. A told stage that ended lease_expired or failed may still owe trials on a relaunch, so none keeps serving.

## What a session's close answers

`spent_micros` is the session's settled spend at its close: its calls with a recorded cost. `unknown_micros` is the full reservation O6 still holds for its calls with no recorded cost at that moment, a call still in flight or priced only in the proxy journal included, and `unknown_calls` counts those calls. real_agent passes `spent_micros` on as the trial's cost_usd, so admission's metered means use settled spend and never price an unknown call. `unknownFromRun` reads the same answers from the run directory's `close` lines and counts each arm's calls of unknown cost for item 5 to print, even when the lease's close later settles them. It refuses a run while a session there has no close line, so every path that closes a lease the driver left open writes one for each session still open on it: the relaunch's recovery, `ledger settle --lease` and `ledger reconcile` (below). The cap path still counts every unknown call at its full reservation: the room check, the lease's close and the envelope.

## Trial images

Each G session runs in its task's image as T-G's manifest pins it (lanes/outcome-skills/images/manifest.ts), so both arms run the same image for each task.

1. On a keyless build host, `gstack-evals outcome images pin --out <manifest.json> --set T-G --commit <sha> <task dir>...` builds each sealed task's image with the lane's buildImage, lays quick/laneb's runtime layer on top of the image id it built (runner/runtime-stages.Dockerfile and runner/runtime-copy.Dockerfile: claude, node and bun under /usr/local/bin and /opt/laneb/bin), checks in that final image that gold passes every required test and the empty change fails one (a test the layer flips refuses the row, named in the message), and writes one row per task: its label, kind, task.json and environment/ digests (file bytes and executable bits) and the final image's id. It writes the manifest with an exclusive create, so it never replaces one written meanwhile. buildImage refuses an upstream task where provider keys are set (E_REAL_TASK_KEYED_HOST), and the envelope host holds the keys the proxy reads, so pin never runs there. Move the images to the envelope host with `docker save` and `docker load`, which keep each image's id. The manifest stays sealed; `images public` prints the form a post may carry, digests and kind counts only.
2. Before any lease opens, `gstack-evals outcome images check <manifest.json> --sha256 <hex>` refuses a manifest whose sha256 is not the one the readiness post records, then requires every row's image to be present with exactly its pinned id and runs cleanRoomPreflight on it by id, as /root with work dir /testbed. It stops at the first miss.
3. For each task, `gstack-evals outcome images bind <manifest.json> --task <task dir> --label <label> --out <run copy>` writes the run copy Harbor gets: its environment is only `FROM` a local tag of the pinned image, and its task.toml names that tag as Harbor's prebuilt `docker_image`, so Harbor runs the pinned image without a build. bind checks the copy itself: task.json and environment/ against the row, every file against task.json's file digests, and no symlinks, so a later edit to the task dir cannot reach the session. It prints `image_id=`. A second bind on the same out refuses with E_USAGE while the first holds out's `.bind-lock`.
4. real_agent takes that id as `image_id`, with `manifest` (the manifest's path) and `manifest_sha256` (its recorded sha256). In U4 mode it refuses before any sandbox or session opens unless `image_id` is a sha256 id, the manifest's bytes hash to `manifest_sha256`, its row for `task_label` pins exactly `image_id`, and the trial container runs exactly it (`docker inspect -f {{.Image}}`).
5. `gstack-evals real score trial <evaluator dir> --task <task dir> --model <id> --image-id <the row's id>` grades every tree in that pinned image on the host that holds it, so scoring builds nothing and runs on the envelope host. It refuses a missing or absent image, a trial that logged no image, an image other than the one the trial logged, and a bound run copy as --task.

## Settling a lease the driver left open

The driver exits 2 and prints E_LEASE_UNSETTLED with each lease id it could not settle, and a launch is refused with E_LEASE_UNSETTLED while one of its stage items holds an open lease. Settle such a lease with the ledger's own commands. No step below edits O6's record, the local ledger, sessions.jsonl or a proxy journal by hand.

1. Stop any driver still serving the run directory with POST /stop or SIGTERM, so no lease is settled while a live driver meters it.
2. On the envelope host, read `gstack-evals ledger status --item <item>` for each item the driver served and `gstack-evals ledger status --program <program>`. Send the readings and the driver's log lines to the reader the operator rule names, who rules under it.
3. When that reader rules a relaunch, launch the driver again on the envelope host with the same `--run`, `--dir`, `--record` and `--ledger`. Before preflight, its recovery settles every open lease the run directory holds, whatever stages the launch lists: it reconciles the lease's proxy journal, writes a `close` line with reason `recovered` for each session sessions.jsonl still shows open on the lease, with its figures from the local ledger at that point so `unknownFromRun` counts its unknown calls, copies any cap stop into the close and prints STAGE_RECOVERED. The launch then serves the stages it lists, unless one of them is stopped or the run holds a none stop, in O6's record or in the local ledger, which refuses the whole launch with CAP_STOP before any lease opens.
4. Otherwise settle each open lease on the envelope host with `gstack-evals ledger settle --lease <lease id>`, pointed at the driver's record and local ledger. The close copies a stop the record holds on the lease, or one the local ledger staged with it. A call whose outcome only the proxy journal holds stays unknown at its full reservation, as the cap path counts it. Once the close is in the record, the settle writes a `close` line with reason `settled` for each session the run directory's sessions.jsonl still shows open on the lease, with that session's figures from the local ledger the close was staged in. A retry answers the same close and writes only the lines still missing. If a settle was cut after the record took its close and before the local ledger marked the lease closed, a retry answers the record's close and marks the lease closed, and a stop the local ledger holds that the record does not is written as the lease's stop record, so O6 refuses a new lease on the item.
5. If the envelope host's local ledger is gone, the owner reconciles the lease after it expires with `gstack-evals ledger reconcile`, from the provider's usage export (docs/budget-ledger.md). Run it on the envelope host while the run directory is still there: the reconcile writes a `close` line with reason `reconciled` for each session sessions.jsonl still shows open on the lease. Its unknown_calls and unknown_micros come from the reconciled close, which prices every call, so they are 0, and it carries no spend of its own, since the owner's figure covers the whole lease.

When a settle or reconcile can't reach the run directory, or a settle runs where the local ledger does not hold the lease, or `ledger settle --from` imports the close, the close still lands and the command warns SESSIONS_OPEN. Run it again on the envelope host (after `settle --from`, run `ledger settle --lease` there); admission item 5 refuses the run until every session has its close line.

A launch refused at preflight, E_RIG_UNPROVEN included, opens no lease, and a refusal while the driver opens its stages settles every lease it opened at $0, so neither leaves a lease to settle. Write the missing admission record with `gstack-evals rig admit` for the slot the message names, then launch again.
