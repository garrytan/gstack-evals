# Decision routing: test-pass labels, a stated reading of the prereg

This lane runs the 2026-11-09 decision-routing preregistration (wiki/plans/2026-11-09-geva-411-decision-routing-prereg). `gstack-evals decision-routing --help` lists its subcommands.

The prereg labels a test-pass decision with "the runner's exit code, from the same test command rerun without the pipe on the snapshot" (section 6). It does not say what happens when the logged command is more than a runner. We read it this way, and labels/container.ts applies it:

1. The replay drops everything from the command's first top-level pipe on (`|` or `|&`, never `||` or a quoted bar). So `pytest tests | tail -5` replays as `pytest tests` and keeps its label, because the left side of the pipe is the runner. Everything after the pipe goes too, so `pytest | tail -1 && echo done` also replays as `pytest`.
2. What remains must be a bare runner under the frozen test-runner rule of section 5 (dr_agent/rules_parser.py is_runner_exit, ported in labels/runner-exit.ts): one simple command from the frozen runner list (pytest, py.test, python -m pytest, python -m unittest, tox, nox), optionally after `cd <dir> &&`, with redirection to a file allowed.
3. Otherwise the label is missing (DR_LABEL_MISSING), never a pass or a fail. `pytest tests; echo $?`, `pytest || true`, `pytest && echo ok`, `make test` and a project script such as `./tests/runtests.py` all drop: their exit code is not the tests' result, or the frozen list does not name the runner.

`score` prints how many test-pass labels this drops, per model, cell and acting layer (jev, particle, frontier, main_turn, rule), in its text and JSON reports. `labels trial` prints the count for one trial. The results post discloses both.

## Reserve mechanics amendment (2026-11-09)

The Captain's ruling on the pre-lease reserve: before each new lease, an item's cap must hold everything settled on it plus the reserve for the sessions that lease can have in flight, each at the per-session allowance ($5). A batch lease runs up to 6 sessions at once, so it reserves 6 × $5 = $30. An answering lease (host/answer.ts, every mode) reserves 1 × $5 = $5, because answering runs one session at a time, and the step enforces that: OneSession refuses a second session while one is in flight on the lease (DR_ANSWER_CONCURRENCY). The reserve exists to cover sessions in flight, and answering has at most one, so the caps stay where they were approved, dr-replay's $40 included.

## Git history strip (D7, 2026-11-10)

SWE-rebench task images ship git refs past the task's base commit. In the scored stage's first 47 images, every one has an ORIG_HEAD past the base, 13 have tags past it with the later commits on disk, and in 6 of those the later commits carry the hidden tests' names. A weaker agent finds such commits with `git log --all` and `git show` (the harness mechanics lane saw it). So from the scored stage on, each task's environment/Dockerfile ends with a strip step (host/history.sh, added by host/tasks.ts): it deletes every ref and pseudo-ref that is not the base commit or an ancestor of it, expires the reflogs and prunes, and fails the image build if anything past the base is left. Before a batch's first session, `decision-routing history` builds each session image the way Harbor does and checks it in a throwaway container with no network: (a) every ref and pseudo-ref points at the base or an ancestor, (b) every commit object is the base or an ancestor, (c) there is no alternates file, submodule object store, worktree or other object store holding this repository's later commits, and (d) none of the task's hidden test markers is in a file outside /testbed, in a file under /testbed that the base commit's tree (`git ls-tree -r`) does not hold byte for byte (untracked, ignored, staged-only or modified, since the index never counts as base content), in an object the base commit does not reach, or in git's own files such as the index and logs. The markers are mounted read-only for the check and never enter an image layer. A task that fails any part fails the gate with DR_HISTORY_LEAK, and no session runs on it. The verifier and the label containers keep the pristine image, since no agent works in them. Calibration and the pilot ran on unstripped images; the results say so.
