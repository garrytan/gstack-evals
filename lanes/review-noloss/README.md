# Review no-loss category

Does a review variant keep the blockers a reference review catches? This lane scores any review arm on a suite of
blockers, paired by blocker, with cost per PR and per blocker found. Plan: [wiki/plans/2026-10-30-gsta-40-review-noloss-plan](../../wiki/plans/2026-10-30-gsta-40-review-noloss-plan/README.md).
No command here calls a model; running an arm or a judge is paid work that needs its own preregistration.

## Layout

- `suites/gsta167-14pr.json`: GSTA-167's 29 blockers on 14 gstack PRs, each pointing at a catalog case in
  `lanes/review-replay/catalog/noloss/` (27 new) or `public/` (two reused mined cases). It is generated by
  `scripts/import-noloss-cases.ts` from `catalog/noloss/mining/cohort.json` and `mining/hand.json`, which restate the
  cohort and each blocker in our own words. GSTA-167's documents stay in the org drive; the suite pins their digests.
- `arm.schema.json`: arm contract version 1 for `arm.json` and one findings line.
- `example/arm-example/`: a synthetic arm that uses every contract field. `noloss ingest --check` passes on it.
- `arms/<suite>/<arm id>/`: ingested arms. `arms/gsta167-14pr/` holds GSTA-167's legacy arms A, B, C and A2 (A'),
  transcribed with labels in view.
- `comparisons/<suite>.json`: the comparisons `noloss export` scores, each with its margin and reason, post hoc
  status and frozen bar, plus the power table's inputs.
- `../../tables/review-noloss.json`: the export, generated. CI fails when it is stale.


A sealed suite's `--out` for `derive` and `flag-scan` must sit outside the repo. `secondary` counts judgments with coverage incomplete as
misses, and refuses (E_NOLOSS_BLIND) an arm that mixes labelled and blind judgments or a pair judged one each way.
`gstack-evals noloss --help` has the details. Every refusal starts with its reason code (E_NOLOSS_SUITE, E_NOLOSS_ARM,
E_NOLOSS_JUDGMENT, E_NOLOSS_COST, E_NOLOSS_BLIND, E_NOLOSS_STALE) and names the file, row and field. `score` exits 0 on
NO_LOSS with the size rule met, 1 on LOSS and 2 otherwise. E_NOLOSS_ADJUDICATION and E_NOLOSS_EXPECT are refusals too.

Exit 2 covers NOT_DISTINGUISHED, NOLOSS_UNDERPOWERED, no verdict and every refusal, so verification never reads exit 2
alone. score's text output ends with `verdict: <LOSS|NOT_DISTINGUISHED|NO_LOSS|none> [NOLOSS_UNDERPOWERED]`, and
`readScoreRun` in verdict.ts reads a run from that line (or the --json record) and the first reason code on stderr into
LOSS, NOT_DISTINGUISHED, NO_LOSS (a claim), NOLOSS_UNDERPOWERED, NO_VERDICT or the refusal's code, and checks that the
exit code agrees. `score --expect <list>` does the same and exits 0 only when the outcome is one the comma-separated
list names, else E_NOLOSS_EXPECT.

## Arm contract v1

An arm is a directory holding these files and nothing else. Unknown JSON fields and TSV columns are kept and ignored.

- **arm.json**: required `contract_version` (1), `id` (letters, digits, _ and -; write A' as A2), `label`, `suite`,
  `date`, `passes`. Optional: `kind`, `provenance` (live or transcribed), `transcribed_from`, `status` (complete or
  stopped), `coverage_gaps`, `suite_sha256`, `source`, `prereg`, `models`, `run_by`, `notes`, `severity_map`.
- **findings/<unit>.jsonl**: one file per suite unit, empty when the arm found nothing there. One finding per line in
  gstack's specialist shape: `severity`, `path` (repo-relative), `line`, `summary`, plus optional `label` (the reader's
  own label when `severity` holds a merged one), `fix`, `reader`, `pass`, `id`, `fingerprint`. A finding's id is `id`,
  else `fingerprint`, else `#<0-based line>`; `#<line>` always works.
- **judgments.tsv**: `pr, blocker_id, outcome, matched_finding, raw_severity, mapped_severity, judge, saw_label, note`,
  plus optional `pass` and `coverage`. One row per blocker per pass. `outcome` is F (matched at CRITICAL), D (matched,
  INFORMATIONAL only) or M. `matched_finding` lists finding ids separated by `;`, and the outcome must follow their mapped
  severity. A missing row is an error, never a miss.
- **cost.tsv**: `pr, scope, total_tokens, meter_source`, plus optional `input_tokens, output_tokens, cache_read_tokens,
  cache_write_tokens, reasoning_tokens, usd, wall_seconds, covers, pass` (`input`, `output`, `cache_read`, `cache_write`,
  `reasoning` and `voice` are accepted aliases). Blank or `unavailable` means unknown. `meter_source` is proxy-journal or
  reader-counter (exact), lane-counter-delta, root-counter-delta (an upper bound) or estimate. A unit's total is its
  `all`-scope row; other scopes are components. `pr` may be `*` with `covers` listing the units.
- **adjudication.tsv** (optional, version 1): `pr, finding, pass, ruling, judge, saw_label, version, batch, note`. One row
  per blocking finding (mapped CRITICAL) per pass that judgments.tsv matches to no blocker. `finding` is the finding's
  id or `#<line>`; `version` is 1; `batch` is the adjudication batch digest. `ruling` is `defect` (a real defect no
  suite blocker names: a new blocker), `not-defect`, or `known-informational` (it raises the unit's known informational
  case as a blocker; only on a unit with an over-blocking blocker). A matched finding gets no row, since judgments.tsv
  already rules it. A blocking finding with no row is unadjudicated: the false-blocker reading says it is incomplete
  and never counts it as not a defect.

A unit ref (`pr` column, findings file name) is `<pr>`, `<pr>@<head prefix>` or `<owner>/<repo>#<pr>@<head>`; write
`__` for `/` in a file name. A ref must name one unit of the suite.

Severity: the raw label is `label`, else `severity`, cut at its first comma. CRITICAL and INFORMATIONAL map to themselves;
any other raw label needs an exact `severity_map` entry (`by_reader` overrides `default`).

An arm with findings and no judgments is raw. It ingests and can be turned into blinded judge packets, and is scored
once its judgments exist.

## Reporting an arm in

1. Write the directory above. Use bare finding ids in `matched_finding`, put prose in `note`, and keep machine paths out.
2. `gstack-evals noloss ingest <dir> --suite gsta167-14pr --check` until it passes. It writes nothing.
3. `gstack-evals noloss ingest <dir> --suite gsta167-14pr` publishes it under `arms/`, in a pull request.

## Scoring

Each blocking blocker gets one value per arm: the share of the arm's passes that FOUND it. PRs are the clusters.
`noloss score` and `noloss export` print, for each comparison of a variant V against a reference R:

1. The frozen bar first, when the round froze one, scored exactly as written.
2. The verdict. NO_LOSS when the margin-shifted exact sign-flip test over PRs rejects "V is worse than R by at least
   the margin" at one-sided 0.05. Otherwise LOSS when the margin-0 test, oriented the other way, gives p < 0.05.
   Otherwise NOT_DISTINGUISHED. The test is exact at any number of PRs (stats.ts) and equals the kit's
   marginShiftedSignFlipP where the kit enumerates. When no blocker differs and R is off ceiling and floor, p is 2^-k
   over k PRs ("no discordant blocker"); a true ceiling or floor stays null. An export Holm-adjusts the no-loss p
   across its comparisons; the LOSS test is not adjusted unless the comparisons file declares a LOSS family (below). Every verdict line gives delta with its PR-clustered
   bootstrap interval, losses, gains, both p-values and the minimum reachable p.
3. The size rule: the share of simulated runs in which an arm exactly as good as R gets NO_LOSS (`--power-sims`, or
   the prereg's `--power`). A NO_LOSS below 80%, or unchecked, exits 2 with NOLOSS_UNDERPOWERED and is not a claim.
4. Cost on the units metered in both arms, at the weaker meter grade. A pr * row is never split and gives no median.
5. Whether the claim "non-inferior within the margin" may be made, and every reason it may not: the verdict, the size
   rule, post hoc status, labelled judging, a development-only suite, unadjudicated unmatched blocking findings.

Labelled and blind judgments are never pooled, and lines from labelled judging open with "labelled judging". A
stopped arm, or one with blockers recorded as coverage incomplete, gets no verdict.

## LOSS family

A comparisons file may declare `loss_family`: `order` (comparison ids in the declared order), `null` and `reason`. With
`null` zero the LOSS test asks whether V is worse than R at all; with `margin` it asks whether V is worse than R by
more than the comparison's margin. The family's LOSS p-values are Holm-adjusted step-down (smallest p first, ties in
the declared order, each adjusted p at least the one before it), and LOSS is decided on the adjusted p. The verdict line
gives the raw and adjusted p and the step; the record has `p_loss_holm` and `loss_family`. Comparisons outside the
family, and files with no family, keep the unadjusted LOSS test.

## False blockers

A false blocker is a blocking finding ruled not-defect, or one that over-blocks a unit's known informational case:
matched in judgments.tsv only to an over-blocking blocker, or ruled known-informational in adjudication.tsv. Per arm
and PR the count is averaged over passes. Each comparison pairs the counts by PR and gives the mean difference (V minus
R, per PR) with its PR-clustered bootstrap interval, an exact two-sided sign-flip p over PRs (stats.ts), the per-PR
table (PR, V count, R count, difference, findings still unadjudicated), and whether the estimate clears the smallest
per-PR drop that counts (`false_blocker_drop` in the comparison, or `--false-blocker-drop`). The preregistration sets
that drop; nothing here defaults it. A transcribed arm gives no reading; an unadjudicated finding, a stopped arm or
pooled labelled and blind adjudication makes it incomplete and untested.

## Plan suites and sealed roots

A plan suite (kind plan, planning lane plan [wiki/plans/2026-10-31-geva-79-planning-lane-plan](../../wiki/plans/2026-10-31-geva-79-planning-lane-plan/README.md))
holds plan units: each is a small repository whose head commit adds plan.md, and each blocker points at a plan case
(kind plan in the one catalog schema). `suite --from-catalog` groups a plan's cases into one unit, sets its group to
the plan's stratum (seeded, real-neutral, home-field, decoy) and leaves pilot units out unless `--stratum pilot` asks.
A decoy's one case is its bait, deserved INFORMATIONAL, so it counts only toward false alarms.

A sealed suite never sits in this repo whole. Its suite file and catalogs live under a sealed root: any absolute
directory outside this checkout, given to every command with `--sealed-root <dir>`; one inside the checkout, or a
symlink into it, is refused, and every sealed output path is checked with its symlinks resolved. The repo holds the stub
`suite --stub` prints: id, kind, counts by blocker kind and group, the suite's sha256 and the sha256 over its catalogs'
case files, and a custody line that starts "procedural custody". The stub is refused when its id, title, purpose,
custody or group names name a sealed unit, cluster, repo, commit or case.
A sealed suite's catalogs resolve under the sealed root, and so do the catalogs of any suite read by path from outside
the repo, sealed or not, when `--sealed-root` is given. Without it, such a suite's catalogs resolve under the repo, and
a catalog that is not there refuses with E_NOLOSS_SUITE, naming `--sealed-root`.
A stub loads only with a sealed root whose suite and catalogs match its digests and counts. Decrypting a panel into a
sealed root happens outside the scorer. `export --publish-sealed-table` writes a sealed suite's table into the repo
only when it names no sealed unit, cluster, commit or case.

Plan judge packets show each finding's section, claim, evidence and fix, mask severity words, strip the frozen
PLAN_HEADING_WORDS of gstack's plan reviews, and carry the unit's tree at its head from `--source`, whose plan.md must
hash to every case's plan digest. `score --false-alarm-gate <n>` (or a comparison's `false_alarm_gate`) reads
must-fix false alarms on decoys only: a LOSS whose reference raises more than n extra per decoy, interval included,
warns FALSE_ALARM_GATE_FAIL and its claim may not be made. With `--prereg`, a `--false-alarm-gate` that is not the
comparison's preregistered gate scores it post hoc. `derive --first-k <k>` is the volume-matched reading; it refuses a
transcribed arm, which has no findings to cut. `power --alpha` and `--dependence` give power at a Holm step with the
flaws of one plan moving together.

## Legacy arms

On `comparisons/gsta167-14pr.json`, labelled judging and post hoc: blocking recall C 19/29, A' 12/29, A 11/29 and B
8/29. At the 10-point margin A' (9 losses, 2 gains), A (11 losses, 3 gains) and B (13 losses, 2 gains) are each LOSS
against C, with p_loss 0.031, 0.031 and 0.0039. B against A is NOT_DISTINGUISHED: 3 discordant PRs cannot reach p
below 0.125. Every frozen bar fails. With 4 comparisons in the family, a Holm adjustment of the LOSS test would leave
only B against C below 0.05. Cost rows are root-counter deltas, upper bounds: on the 11 PRs metered in both, C spends
28.3M tokens per PR and A' 17.7M, and both about 19.5M per blocker found.

## Blinded judging

`judge-packet` pools every arm's findings for a unit, from every pass, in a seeded shuffle under opaque ids. A packet
keeps only path, line and text, with severity words masked, and refuses a text that names an arm id or label,
"arm <id>", a model id or a hyphenated reader. The key that maps ids back to arms is written outside the packets.
The batch digest binds the suite, each arm's tree digest, the seed and the key's mapping.

`judge-join` takes each judge's JSON reply, which names the batch and each packet's digest, and applies severity
mechanically: the highest mapped severity among a blocker's matches wins. It names and waits for a second judge on
every blocker where the arms differ plus a seeded 20% sample, and a third read wherever the judges differ. Then it
writes `<out>/<arm id>/` with judgments.tsv (saw_label no) for every arm at once; ingest each with `--replace`.

`judge-packet --adjudicate` builds the same blinded packets from the blocking findings judgments.tsv leaves unmatched, one
packet per unit that has any, each with the unit's known informational cases. A reply rules every finding:
`{batch, judge, packets: [{file, sha256, findings: [{id, ruling}]}]}`. `judge-join` on that key asks a second judge for
every finding the primary ruled not-defect or known-informational plus a seeded 20% sample of the rest, and a third read
wherever the two differ, then writes adjudication.tsv for every arm at once; ingest each with `--replace`.

## Judge runner

`judge-run` is the paid step between the two. It sends each judge the frozen brief, the batch's batch.json and one
packet per request through an in-process metering proxy on a lease of one ledger item, with no tools, no system prompt
and at most 16,000 output tokens. The primary reads every packet; the second and third read the packets that hold the
blockers or findings judge-join will ask them for (the same `judgeSets` code), and their reply files keep only those.
The runner writes each reply's batch, judge, file and digest itself. An answer judge-join would refuse is asked again
once, and a second refusal goes to unjudged.json, which `judge-join --unjudged` turns into coverage incomplete rows (or
no adjudication row). `impact` and `verifiable` go to impact.tsv and verifiable.tsv, never into a reply, and each row carries the sha256 of the finding it rated; `derive` refuses a rating whose finding changed. Adjudication
packets go out with an evidence sheet built from each finding's masked evidence and the unit head's code in a `--source`
clone, and the run writes unverifiable.tsv for the frozen sensitivity count. The proxy retries a 429 or 5xx within a budget of 3 sends in 900 s; past it, or on a
transport error, the run stops. `--dry-run` prints each request's worst case at 3 sends and the item's cap beside the
total, and spends nothing. A ledger item binds to one run, so the matching and adjudication batches need an item each.

`judge-run --ceo` is the CEO outcome eval's judge read (src/trial/review/README.md, CEO outcome units): one judge per
run over the packets `gstack-evals ceo packets` wrote. It sends the brief's text above its rule with each D packet and
the text below it with each remedy packet, through the same proxy, lease and retry budget, and writes replies.json
with every packet answered or missing with its cause. A reply that breaks the brief's failure rule gets one retry in a
fresh request; a second failure marks that judge's calls for the packet missing. `gstack-evals ceo readings` joins the
three judges' replies.json files. `--out` must sit outside the repo.
