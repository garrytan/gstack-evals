# Review no-loss category

Does a review variant keep the blockers a reference review catches? This lane scores any review arm on a suite of
blockers, paired by blocker, with cost per PR and per blocker found. Plan: [wiki/plans/2026-10-30-gsta-40-review-noloss-plan](../../wiki/plans/2026-10-30-gsta-40-review-noloss-plan/README.md).
No command here calls a model; running an arm or a judge is paid work that needs its own preregistration.

## Layout

- `suites/gsta167-14pr.json`: GSTA-167's 29 blockers on 14 gstack PRs, each pointing at a catalog case in
  `lanes/review-replay/catalog/noloss/` (27 new) or `public/` (two reused mined cases). It is generated by
  `scripts/import-noloss-cases.ts` from `catalog/noloss/mining/cohort.json` and `mining/hand.json`, which restate the
  cohort and each blocker in our own words. GSTA-167's documents stay in the org drive; the suite pins their digests.
- `arm.schema.json`: arm contract version 1 for `arm.json` and one findings line.
- `example/arm-example/`: a synthetic arm that uses every contract field. `noloss ingest --check` passes on it.
- `arms/<suite>/<arm id>/`: ingested arms.

## Commands

```
gstack-evals noloss suite --check [--suite <id|path>] [--prereg <file>]
gstack-evals noloss suite --from-catalog <dir>... --id <id> --released <YYYY-MM-DD> [--with <suite>] [--out <path>]
gstack-evals noloss ingest <arm dir> --suite <id|path> [--check] [--root <dir>] [--digest-only <finding id>|all]... [--replace <reason>]
```

`gstack-evals noloss --help` has the details. Every refusal starts with its reason code (E_NOLOSS_SUITE, E_NOLOSS_ARM,
E_NOLOSS_JUDGMENT, E_NOLOSS_COST) and names the file, row and field.

## Arm contract v1

An arm is a directory holding these files and nothing else. Unknown JSON fields and TSV columns are kept and ignored.

- **arm.json**: required `contract_version` (1), `id` (letters, digits, _ and -; write A' as A2), `label`, `suite`,
  `date`, `passes`. Optional: `kind`, `provenance` (live or transcribed), `transcribed_from`, `status` (complete or
  stopped), `coverage_gaps`, `suite_sha256`, `source`, `prereg`, `models`, `run_by`, `notes`, `severity_map`.
- **findings/<unit>.jsonl**: one file per suite unit, empty when the arm found nothing there. One finding per line in
  gstack's specialist shape: `severity`, `path` (repo-relative), `line`, `summary`, plus optional `label` (the reader's
  own label when `severity` holds a merged one), `fix`, `reader`, `pass`, `id`, `fingerprint`. A finding's id is `id`,
  else `fingerprint`, else `#<0-based line>`; `#<line>` always works.
- **judgments.tsv**: `pr, blocker_id, outcome, matched_finding, raw_severity, mapped_severity, judge, saw_label, note`,
  plus optional `pass` and `coverage`. One row per blocker per pass. `outcome` is F (matched at CRITICAL), D (matched,
  INFORMATIONAL only) or M. `matched_finding` lists finding ids separated by `;`, and the outcome must follow their mapped
  severity. A missing row is an error, never a miss.
- **cost.tsv**: `pr, scope, total_tokens, meter_source`, plus optional `input_tokens, output_tokens, cache_read_tokens,
  cache_write_tokens, reasoning_tokens, usd, wall_seconds, covers, pass` (`input`, `output`, `cache_read`, `cache_write`,
  `reasoning` and `voice` are accepted aliases). Blank or `unavailable` means unknown. `meter_source` is proxy-journal or
  reader-counter (exact), lane-counter-delta, root-counter-delta (an upper bound) or estimate. A unit's total is its
  `all`-scope row; other scopes are components. `pr` may be `*` with `covers` listing the units.

A unit ref (`pr` column, findings file name) is `<pr>`, `<pr>@<head prefix>` or `<owner>/<repo>#<pr>@<head>`; write
`__` for `/` in a file name. A ref must name one unit of the suite.

Severity: the raw label is `label`, else `severity`, cut at its first comma. CRITICAL and INFORMATIONAL map to themselves;
any other raw label needs an exact `severity_map` entry (`by_reader` overrides `default`).

An arm with findings and no judgments is raw. It ingests and can be turned into blinded judge packets, and is scored
once its judgments exist.

## Reporting an arm in

1. Write the directory above. Use bare finding ids in `matched_finding`, put prose in `note`, and keep machine paths out.
2. `gstack-evals noloss ingest <dir> --suite gsta167-14pr --check` until it passes. It writes nothing.
3. `gstack-evals noloss ingest <dir> --suite gsta167-14pr` publishes it under `arms/`, in a pull request.
